# 06 · 复用规则

> 状态：Accepted · Chris Review 2026-08-03
>
> 关联决策：[ADR-015](../adr/ADR-015-MOM组件复用与共享包准入.md)

## 1. 目标

复用用于降低语义漂移和高风险交互差异，不以减少文件数量为目标。默认从页面本地或模块私有开始，出现稳定、真实、跨边界的重复后再提升。

## 2. 复用层级

|层级|适用内容|允许依赖|
|---|---|---|
|Antdv 原语|按钮、输入、表格、弹层等基础行为|Antdv、Token Adapter|
|MOM 语义组件|Page、DataState、ActionBar、ConfirmAction|Antdv、Token、纯工具|
|稳定领域组件|跨应用且语义一致的领域可视化或输入|公开 View Model、语义组件|
|模块私有组件|模块内重复任务片段|本模块公开/私有模型|
|页面本地组合|单页面编排|所在模块能力|

## 3. 共享准入

普通组件进入跨应用 package 前应满足全部条件：

1. 至少两个真实消费者已经存在，而非计划中的消费者；
2. 两处的业务语义、状态模型和无障碍行为一致；
3. API 可使用 View Model、显式状态和事件表达；
4. 不依赖应用 Router、Store、API、权限编码或渠道内部字段；
5. 有组件测试、示例、所有者、变更策略和 Bundle 影响说明；
6. 提升后的依赖方向不产生循环或应用反向依赖。

认证、安全确认、幂等交互、错误归一化和无障碍等高风险横切能力可以在只有一个当前消费者时共享，但必须有明确的第二消费者边界或一致性风险证据，并记录例外理由。

既有 package 不因历史存在自动满足共享准入。S02 必须为 `common-ui` 及其他拟保留共享包记录真实消费者、所有者、公共 API 和例外到期 Slice；没有第二消费者且不属于已登记高风险例外的能力迁回实际应用或模块。示例、空导出和计划中的页面不计为消费者。

## 4. 共享组件 API

共享组件只接收：

- 已映射的 View Model；
- `loading / disabled / error / conflict` 等显式状态；
- 用户事件和语义回调；
- 必要的可访问名称与渠道密度输入。

共享组件不得自行请求数据、导航、解析 Permission、读取全局 Store、写 Session、猜测重试策略或吞掉错误。Admin 与 Portal 不共享含内部字段的 View Model。

## 5. 禁止的“复用”

- 不创建可配置一切的 Universal Table、Universal Form 或万能 CRUD；
- 不为了单次重复提前抽取 `shared/utils`、`common/hooks`；
- 不复制 Vben 组件到 `@mom/*` 后声称已完成退出；
- 不使用全局 Store 作为跨模块通信总线；
- 不以动态字符串、`any` 或透传整个 DTO 规避边界；
- 不把页面布局差异塞进大量布尔 Props。

## 6. AI 与开发者搜索顺序

实现页面前依次检查：Antdv 原语 → `common-ui` 语义组件 → 已批准领域组件 → 当前模块组件 → 页面本地实现。只有满足准入条件时才向上提升；发现近似但语义不同的组件时优先保持独立并记录差异。

## 7. 退出与变更

共享能力必须有负责人和废弃路径。破坏性变更先迁移消费者，再删除旧入口；临时 Adapter 或单消费者例外标注所属 Slice、消费者、理由和最晚复审/删除点。没有真实消费者的包应按消费者收敛，而不是用示例或空导出维持存在。
