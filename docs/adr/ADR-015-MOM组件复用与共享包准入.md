# ADR-015：MOM 组件复用与共享包准入

- 状态：Accepted
- 日期：2026-08-02
- 接受日期：2026-08-03
- 决策人：Chris
- 关联架构：[复用规则](../frontend-architecture/06-reuse-rules.md)
- 替代：[ADR-006：共享组件准入边界](ADR-006-共享组件准入边界.md)

## 1. 背景

现有 ADR-006 建立了共享组件基本边界。P1.6 需要进一步覆盖真实消费者门槛、高风险例外、View Model 隔离、共享包收敛和 AI 实现搜索顺序。

## 2. 问题

需要在三应用之间保持体验一致，又避免万能组件、占位包、共享 Store 和内部字段泄漏。本 ADR 不要求消除所有重复。

## 3. 候选方案

### A. 发现重复立即共享

文件少，但不稳定语义会变成复杂 Props 和跨应用耦合。

### B. 应用完全独立

边界简单，但安全、无障碍和状态语义容易漂移。

### C. 私有优先、稳定后提升

允许合理重复，以真实消费者和稳定契约换取长期复用。

## 4. 决策

选择 C。普通组件进入跨应用 package 前必须有至少两个真实消费者，并满足语义一致、View Model 输入、显式状态/事件、无应用基础设施依赖、测试/文档/所有者/Bundle 影响等准入条件。

认证、安全确认、幂等、错误归一化和无障碍等高风险横切能力可基于一致性风险提前共享，但必须记录例外理由。本 ADR 自 D01 起生效，ADR-006 转为 Superseded 并保留历史。

既有 package 不因历史存在自动满足双消费者规则。S02 必须盘点 `common-ui` 等拟保留共享包的真实消费者、所有者、公共 API 和例外到期点；示例、空导出和计划中的页面不计为消费者。单消费者且不属于已登记高风险例外的能力迁回实际应用或模块。

## 5. 决策理由

该方案把复用价值限定在语义和风险一致性，而非代码行数；应用与模块仍有足够空间随产品发现演进。

## 6. 正向后果

- 共享包具有真实消费者和明确所有权。
- Admin/Portal 内部模型不会因视觉相似而混用。
- 高风险交互可获得统一验证。

## 7. 负向后果与风险

- 短期保留合理重复。
- 提升组件需要迁移消费者。
- 例外若缺少审计可能成为绕过双消费者规则的通道。

## 8. 实施约束

- 共享组件不请求数据、不导航、不读取 Store/Permission/Session。
- 禁止 Universal Table/Form/CRUD 和万能 Hook。
- 无真实消费者的占位包按消费者收敛。
- 临时 Adapter 或单消费者例外登记 Slice、消费者、理由和最晚复审/删除点。

## 9. 验证方式

共享准入清单、依赖图、组件测试、可访问性测试、Bundle 差异和消费者清单必须同时可审计。

## 10. 替代或回滚条件

若未来建立独立发布型设计系统或组件仓库，需新 ADR 定义版本、兼容、发布和废弃策略；在此之前不拆独立仓库。
