# IAM 动态菜单与国际化能力待办

- 状态：Pending
- 本轮前端行为：稳定菜单注册表 + `/api/iam/me` Permission
- 本轮禁止：虚构动态菜单接口

## 1. 当前事实

IAM 当前没有 MOM Admin 动态菜单接口。六个 IAM 管理入口由前端稳定 `menuCode` 注册表定义，使用 Permission 过滤；未知菜单标题才回退服务端标题。

## 2. 后端待办

后端未来菜单协议至少需要：

- 稳定 `menuCode`
- 路由标识或受控路由 Key
- 排序、层级、图标 Key、隐藏/外链等安全元数据
- 所需 Permission Code
- `i18nKey` 或受控多语言标题
- 菜单 Schema Version / ETag
- Client、user_type 和应用范围

后端不得返回任意前端组件路径、可执行脚本或未经白名单校验的外链。

## 3. 国际化策略

优先方案：

1. 后端返回稳定 `menuCode` / `i18nKey`。
2. 前端维护 `zh-CN`、`en-US` 翻译。
3. 未知编码回退服务端标题并在开发环境告警。
4. 未来如采用后端多语言字段，需要明确默认语言、缺失回退和内容审核。

## 4. 缓存与变更

- 支持 ETag 或版本号。
- 权限变化后返回新菜单版本。
- 403 权限同步重新获取 `/api/iam/me` 和菜单。
- 不使用长期持久化旧权限菜单作为授权兜底。
- 网络失败保留登录状态并展示可重试页。

## 5. 验收

- 中英文切换同步更新菜单、页签与标题。
- Permission 撤销后菜单和路由立即失效。
- 未知菜单不出现空白标题。
- 组件、外链与重定向全部白名单化。
- OpenAPI、Schema Version、权限与安全审计完整。
