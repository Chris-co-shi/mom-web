# API 与权限映射规范

## 1. 目的

API 映射将页面需求、后端接口、权限、数据范围、幂等和错误处理关联起来，是页面进入实现的必备材料。

## 2. 存放方式

```text
docs/api-mapping/<vertical-slice>/
├── 管理端API映射.md
├── 供应商门户API映射.md
└── 客户门户API映射.md
```

## 3. 页面映射表

每个页面至少记录：

| 字段 | 说明 |
|---|---|
| 页面/区域 | 页面、对话框或组件 |
| 需求编号 | 对应 `WEB-*` |
| 查询 API | 加载数据的接口 |
| 命令 API | 创建、更新或执行命令的接口 |
| HTTP 方法 | GET/POST/PUT 等 |
| OAuth Client | 哪个应用 Client |
| Scope | OAuth Scope |
| 权限码 | 页面或操作权限 |
| 数据范围 | 工厂、组织、供应商、客户等 |
| 请求 DTO | 后端契约 |
| View Model | 页面映射模型 |
| 幂等键 | 是否需要、生命周期 |
| Correlation ID | 传播与展示 |
| 业务错误码 | 页面处理方式 |
| 异步结果 | 任务 ID 和查询方式 |
| 文件行为 | 上传/下载规则 |
| Traceability 字段 | 批次、事件、命令等关联字段 |

## 4. 示例

| 页面 | 命令 | 权限 | 幂等 | 可能错误 | UI 处理 |
|---|---|---|---|---|---|
| 供应商送货单创建 | `POST /api/.../deliveries` | `supplier:delivery:create` | 必须 | 校验失败、重复、状态冲突、429 | 字段提示、返回已有单据、等待后重试 |

接口路径必须来自真实 OpenAPI 或后端契约，示例不能直接作为实现依据。

## 5. 查询 API

记录：

- 查询条件。
- 服务端分页和排序。
- 默认时间范围。
- 工厂或组织上下文。
- 空结果语义。
- 部分结果。
- 缓存和刷新策略。
- 取消过期请求。

## 6. 命令 API

记录：

- 当前业务状态。
- 用户权限。
- 请求前确认。
- idempotency key。
- 乐观锁或版本字段。
- 同步/异步响应。
- 成功后的最终状态确认。
- 超时后的查询方式。
- 是否允许重新发起。

命令默认不得自动重试。

## 7. 权限映射

页面必须区分：

- 路由权限。
- 查看权限。
- 操作权限。
- 文件下载权限。
- 诊断信息权限。
- 数据范围。

禁止只写“管理员可用”而不记录权限码。

## 8. 错误码映射

至少考虑：

- 认证失效。
- 权限不足。
- 字段校验。
- 业务规则拒绝。
- 数据版本冲突。
- 重复提交。
- 限流。
- 依赖不可用。
- 异步任务失败。
- 结果未知。

每个错误必须对应：

- 用户提示。
- 可执行动作。
- 是否保留表单。
- 是否刷新数据。
- 是否可以重试。
- 是否展示 correlation ID。

## 9. DTO 与 View Model

```text
OpenAPI / API DTO
→ Schema Validation
→ Boundary Mapper
→ Page View Model
```

映射材料应说明：

- 字段重命名。
- 枚举映射。
- 时间和时区处理。
- 单位和精度。
- 可空字段。
- 外部门户的数据裁剪。

## 10. 上传与下载

记录：

- 文件类型。
- 大小限制。
- 上传进度。
- 失败恢复。
- 文件扫描或服务端校验。
- 授权下载。
- 文件名安全处理。

## 11. 验收

- 页面所有数据来源可追踪。
- 命令具备幂等和未知结果处理。
- 权限和数据范围明确。
- 错误码有 UI 行为。
- API DTO 与 View Model 有边界。
- 不存在浏览器直连内部服务。
