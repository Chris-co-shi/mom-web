# MOM-Web 信息架构

> 状态：Approved with Deferred Items  
> 批准日期：2026-08-03 · Chris Review  
> 阶段：MOM Platform P1.6  
> 前置定位：参见 [product-positioning.md](./product-positioning.md)

## 1. 设计原则

信息架构按以下链条形成：

```text
用户任务 → 业务能力 → 产品导航 → 权限过滤
```

后端服务、代码目录、权限编码均不是一级导航来源。System Application Catalog 可以承载经产品批准的导航元数据，但不能自行创造产品结构。

## 2. 推荐一级业务域

|一级业务域|用户要解决的问题|主要角色|阶段|
|---|---|---|---|
|我的工作|今天先做什么，哪里有风险，哪些决定等待我|全部内部角色，按职责个性化|Future；需聚合能力确认|
|供应与来料|如何协同交货、验收、检验和原料入库|供应商联系人、仓储、质量、工厂管理|Phase 02|
|制造运营|如何计划、下达、执行并掌握工单与批次状态|计划员、生产主管、生产人员|Phase 03|
|质量决策|如何检验、判定、放行并处理不合格|质量检验员、质量经理、生产主管|Phase 02 起|
|库存与履约|库存在哪里、如何移动、何时可发运|仓储、生产、客户协同人员|Phase 02/04|
|追溯与响应|如何从批次定位影响范围并发起投诉/召回处理|质量经理、追溯负责人、客户联系人|Phase 04|
|平台治理|谁能使用系统、如何发布产品目录与运行规则、如何审计|Platform Admin、Factory Admin、Integration Admin|P1.6|

一级域名称是产品候选，不是当前路由承诺。Chris Review 后才能冻结。

## 3. 二级业务域与任务

### 3.1 我的工作

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|待处理|快速进入本人有责任的工作|查看、排序、认领或进入待办|全部内部角色|
|异常与风险|发现偏差并及时升级|查看逾期、阻塞、质量与库存异常|主管、质量、仓储、管理员|
|需要决策|聚焦必须由本人判断的事项|审批、判定、放行、异常处置|主管和经理角色|
|近期活动|了解自己和团队刚发生的状态变化|查看处理结果与上下文|全部内部角色|

工作台不是通用统计大屏，也不以 CPU、内存、服务实例等技术指标作为主内容。当前没有足够证据证明待办聚合接口已存在，因此本域为 Future。

### 3.2 供应与来料

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|供应交付|让预期到货可见且可协同|创建/确认交货、查看到货状态、补充文档|供应商、仓储|
|收货与验收|确认实物和业务单据一致|收货、差异记录、进入检验或入库|仓储、Mobile Worker|
|来料检验|判断原料是否可接收|抽样/结果查看、判定、异常处理|质量检验员、质量经理|
|原料入库|把合格物料转为可用库存|确认入库、查看库位与状态|仓储、Mobile Worker|

### 3.3 制造运营

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|生产计划与工单|把需求转成可执行工作|创建/调整计划、下达工单、查看约束|计划员、生产主管|
|生产执行概览|掌握工单和批次真实进展|查看状态、偏差、阻塞和上下游关系|生产主管、工厂管理|
|现场执行协同|让 PC 决策与现场动作形成闭环|下发任务、查看 Mobile/PCS 回执、处理异常|生产主管、生产人员|
|设备过程上下文|理解设备动作对工单的影响|查看 PCS/WCS 状态引用和异常，不直接控制设备|生产主管、设备工程师|

### 3.4 质量决策

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|检验任务|知道检什么、何时检、结果是否完整|查看任务、录入/复核结果|质量检验员|
|质量判定与放行|对物料/批次作出可审计决定|判定、放行、驳回、查看依据|质量经理|
|不合格与处置|控制影响并推进闭环|隔离、评审、处置、跟踪|质量、生产、仓储|
|质量反馈|连接客户反馈与内部批次|受理、调查、反馈状态|客户联系人、质量经理|

### 3.5 库存与履约

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|库存可视|知道可用量、位置和状态|查询库存、批次、冻结/待检状态|仓储、生产、计划|
|仓内作业|正确完成移动与出入库|上架、移库、拣选、复核；现场动作用 Mobile|仓储、Mobile Worker|
|成品入库|把已放行成品转入可履约状态|确认放行关系、触发/查看 WCS 入库|仓储、质量|
|客户发运|让客户和内部掌握履约状态|计划、复核、发运、查看状态|仓储、客户联系人|

### 3.6 追溯与响应

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|批次谱系|从任一批次理解上下游关系|查询来源、去向和影响对象|追溯负责人、质量经理|
|影响分析|确定异常影响范围|筛选受影响库存、生产与客户交付|质量经理、工厂管理|
|投诉与召回|受控地处理外部质量事件|调查、沟通、召回决策与跟踪|客户、质量、追溯负责人|

### 3.7 平台治理

|二级域|用户目标|核心任务|对应角色|
|---|---|---|---|
|身份与访问|确保正确的人在正确范围内做正确的事|用户、角色、权限查看、会话、客户端|Platform Admin、Factory Admin|
|产品目录与体验|安全发布应用导航、文案和个人显示偏好|Catalog/Navigation 发布、I18n 发布、Preference|Platform Admin、Factory Admin、普通用户|
|运行规则|管理非秘密参数和受限字典|参数、字典维护与审计|Platform Admin、Factory Admin|
|安全与运行审计|发现并调查安全与集成异常|安全审计、会话处置、业务集成诊断|Platform Admin、Integration Admin|

IAM/System 被放在平台治理任务下，而不是与 Production 并列为技术菜单。

## 4. 工作台设计

MOM-Web 长期需要统一的内部工作台，但它应是**同一产品入口下按职责聚合的任务面**，不是所有角色共享同一组卡片。

|角色视角|优先内容|不应作为主内容|
|---|---|---|
|平台管理员|高风险会话、安全事件、待发布目录/I18n、配置变更影响|纯基础设施资源图表|
|工厂管理员|跨供应、质量、生产、库存的阻塞与待决策|全部明细列表堆叠|
|生产主管|工单偏差、现场阻塞、待协调质量问题|平台权限统计|
|质量经理|待判定、待放行、不合格、客户质量反馈|与本人无关的生产产量墙|
|仓储负责人|到货、待上架、冻结库存、待发运异常|完整系统审计日志|
|普通执行人员|本人任务、优先级、截止时间、可继续入口|管理驾驶舱|

在待办责任、优先级、状态新鲜度和聚合 API 得到后端确认前，不把工作台列为 P1.6 必须实现页面。

## 5. 导航原则

### 5.1 一级导航来源

1. 产品架构定义稳定的业务域与用户任务。
2. 客户端静态注册表定义哪些页面真实可执行。
3. System Application Catalog 发布经批准的应用与导航元数据。
4. IAM 权限在运行时过滤可见性并约束操作；后端始终执行最终授权。

固定产品分类与动态发布元数据共同工作，不采用“纯固定菜单”或“权限自动生成菜单”。

### 5.2 跨域跳转

- 从业务对象的上下文关系跳转，例如从生产批次进入相关设备过程、检验、库存或谱系。
- 使用稳定业务标识携带上下文，不依赖菜单层级和列表筛选副作用。
- 保留来源和返回路径，避免用户丢失当前任务。
- 目标能力不可见时给出受控的 Forbidden 或 Not Found；不得泄露越权对象存在性。
- 跨应用跳转只用于明确的渠道边界，不把 Portal 页面嵌入 Admin。

### 5.3 禁止事项

- 不允许权限编码、角色名称或微服务列表自动生成导航。
- 不允许导航节点指向客户端未注册的未知页面；必须 fail closed。
- 不允许用一个 500 项菜单覆盖所有角色。
- 不允许为技术实现方便重复创建同一业务对象页面。
- 不允许把设备控制入口伪装为普通跨域跳转。

## 6. 待决策与待确认

- **Need Product Decision**：一级业务域中文命名和排序。
- **Need Product Decision**：“集成与诊断”最终作为平台治理二级域，还是在业务规模扩大后成为独立支持域。
- **Need Backend Confirmation**：跨域对象关联标识、反向链接和防枚举响应契约。
- **Need Backend Confirmation**：工作台聚合数据、责任人和优先级模型。
- **Unknown**：不同工厂角色的高频任务是否显著不同，需通过访谈/观察验证。
