# 构建发布与环境配置

## 1. 目标

确保三套应用可独立构建、配置、发布和回滚，并与 `mom-infra` 的环境晋级模型对齐。

## 2. 独立构建产物

| 应用 | Workspace | 构建产物 | 发布边界 |
|---|---|---|---|
| MOM 管理端 | `@mom/mom-admin` | 独立静态资源目录/镜像 | 内部访问 |
| 供应商门户 | `@mom/supplier-portal` | 独立静态资源目录/镜像 | 外部门户 |
| 客户门户 | `@mom/customer-portal` | 独立静态资源目录/镜像 | 外部门户 |

不要求三个应用始终同时发布。

## 3. 环境模型

与 `mom-infra` 对齐：

```text
local → dev → test → prod-like
```

### local

- 开发者本地。
- 可使用本地 Gateway 或开发代理。
- 不使用真实凭证。

### dev

- 共享集成。
- 验证 IAM、Gateway 和后端接口。

### test

- E2E、视觉回归、权限和故障场景。
- 使用可重复测试数据。

### prod-like

- 三节点 k3s 演示和生产模拟。
- 使用固定镜像 Digest。
- 保留发布、回滚和验证证据。

## 4. 环境变量

浏览器可见配置只能包含公开运行参数，例如：

```text
VITE_MOM_GATEWAY_URL
VITE_OAUTH_ISSUER
VITE_OAUTH_CLIENT_ID
VITE_OAUTH_REDIRECT_URI
VITE_APP_ENV
VITE_APP_VERSION
```

禁止：

- Client Secret。
- 数据库密码。
- 内部服务地址。
- 消息中间件凭证。
- 私钥。

所有 Vite 环境变量都会进入浏览器产物，应按公开信息处理。

## 5. 配置方式

需要在构建时决定的配置：

- 应用版本。
- 资源路径。
- 构建功能。

需要在部署时可变的配置，应考虑：

- 运行时配置文件。
- 由 Nginx/容器启动注入公开配置。
- 明确缓存失效。

V1 具体方式需要在首个部署 Slice 中确认并记录 ADR。

## 6. 版本标识

每个发布产物至少包含：

- 应用名称。
- SemVer 或项目版本。
- Git Commit SHA。
- 构建时间。
- 目标环境。

版本应进入诊断信息和错误报告。

## 7. 构建命令

全仓：

```bash
pnpm install --frozen-lockfile
pnpm validate
pnpm lint
pnpm stylelint
pnpm tokens:check
pnpm check:type
pnpm test
pnpm test:component
pnpm build
pnpm bundle:check
```

单应用构建可使用 Workspace Filter，但 CI 和正式发布脚本应固定命令并记录产物。

## 8. 静态资源

- 带内容 Hash 的资源可长期缓存。
- HTML 和运行时配置必须使用合适的短缓存或失效策略。
- 发布后不能出现 HTML 指向已删除旧资源。
- 三应用生产构建固定 `sourcemap: false`；Bundle 门禁扫描部署目录，任何 `.map` 都会失败。
- Vite manifest 只用于确定入口静态依赖闭包和生成可重复 Bundle 证据，不允许把动态业务路由混入初始预算。

## 9. 健康检查

静态站点健康检查至少验证：

- HTML 可访问。
- 关键 JS/CSS 资源可访问。
- 应用版本正确。
- 运行时配置可加载。
- Gateway 连接状态通过应用内部诊断或独立探针验证。

仅返回 200 不能证明登录和业务链路可用。

## 10. 发布流程

```text
冻结锁文件安装
→ 静态检查与测试
→ 构建三应用或目标应用
→ 生成版本与 SBOM/依赖清单
→ 构建不可变镜像
→ 部署目标环境
→ 冒烟测试
→ E2E/视觉检查
→ 保存证据
```

## 11. 回滚

- 发布产物不可变。
- 保留上一稳定镜像 Digest。
- 回滚不能依赖重新构建旧代码。
- 前端与后端接口应遵循兼容窗口。
- 回滚后验证登录、工作台和关键 API。

## 12. 接口兼容

前后端独立发布时：

- 后端新增字段应向后兼容。
- 删除或重命名字段必须经过迁移。
- 枚举新增时前端提供 Unknown/Unsupported 回退。
- 页面不得因未知枚举直接崩溃。
- API 版本变化进入契约测试和发布说明。

## 13. 门户安全

供应商和客户门户需要额外关注：

- TLS。
- CSP 等浏览器安全头。
- 独立 Client 和域名。
- 文件下载授权。
- 防止内部页面和 Source Map 暴露。
- 错误信息最小披露。

## 14. 发布验收

- 目标应用版本可查询。
- CI 全部通过。
- 环境变量无密钥。
- 登录和退出正常。
- 无效路由和错误边界正常。
- 关键业务页面冒烟通过。
- 监控无显著新增错误。
- 回滚路径已确认。
