# MOM Web 前端架构

> 适用于路由、请求、认证、模块边界和全局状态修改。普通页面样式任务只读 B2 UI 契约。

## 依赖方向

```text
app/router/layouts
      ↓
business modules
      ↓
shared components / api / i18n / theme
      ↓
shared ui primitives
```

- 业务模块不得相互导入页面内部实现。
- `shared` 不依赖具体业务模块。
- 路由注册表是可执行菜单的唯一来源；System 不下发前端路由。
- 业务模块负责业务字段、权限、API 和失败语义；共享组件只负责可复用交互结构。

## 页面内职责与提取判断

按 `Page + Composable + Domain Component + API` 分工，但不要求每页都有四种文件：

- Page（`.vue`）组合页面与组件，保留列定义、展示文案、当前页简单筛选、少量局部响应式状态、事件绑定、权限展示及路由/生命周期协调。
- 页面专属 Composable（`use-*.ts`）承载复杂业务状态和操作编排，例如服务端查询与分页、引用加载、多步骤提交、请求取消/乱序、版本冲突和结果未知后的阻断与恢复。其状态按页面实例创建，不自动进入全局 Store。提取依据是职责和失败行为是否交织，不是文件行数。
- 模块 `components` 承载有独立职责的业务表单、弹窗或领域交互；只有形成清楚的输入/事件契约、能减少页面复杂度或被实际复用时才新增。简单字段和仅透传 Props/Emits 的包装留在页面。
- 模块 `api` 只封装 HTTP、类型化请求响应及契约，不持有 Vue 页面状态。纯转换、计算和格式化使用普通 TS 函数，无需包装成 Composable。

基础控件放 `shared/ui`，跨模块表格、分页、弹窗等交互结构放 `shared/components`，业务组件留在所属模块。`shared` 不导入业务模块、权限码、业务 API 或领域状态；业务模块不直接复用其他模块的页面内部组件。先复用、再以少量稳定变体扩展，最后才创建新组件；不建立 BasePage、万能 CRUD Composable 或重复外壳。时间、普通数字和 Decimal String 展示优先复用 `shared/formatters`；变更已有显示时区或舍入规则须单独确认语义。

## 路由与权限

- 静态路由由各模块导出，在 `route-registry.ts` 汇总。
- 路由 Meta 描述标题、模块、导航分组、顺序、权限和 i18n Owner。
- 路由守卫与 `AuthorityGuard` 只改善体验，后端仍执行最终授权。
- 当前模块和路由见 [当前实现地图](当前实现地图.md)。

## API

- 所有请求通过 `src/shared/api/http-client.ts`。
- 模块前缀集中在 `src/shared/api/config.ts`；开发代理规则在 `vite.config.ts`。
- API 模块返回类型化数据并保留稳定错误码、HTTP 分类和 Correlation ID。
- 写请求默认不自动重试；网络中断或超时导致结果未知时，页面要求刷新核对。

## 状态

- 认证、主题等真正跨页面状态可使用 Pinia 或专用共享模块。
- 表格查询、分页、详情和编辑草稿默认留在页面或页面专属 Composable；仅跨页面共享且有一致生命周期的状态才考虑 Pinia。
- 不因页面相似建立配置驱动的全局 CRUD Store。

## i18n 与主题

- Web 持有 Key 与 Owner 映射；业务译文从对应服务 Runtime 获取。
- 本地应急文案只用于关键失败恢复，不形成第二套业务译文。
- Design Token 数值权威位于 `src/styles/`；组件和业务页面不得复制独立色板。

## 业务写入失败与恢复

- 只有调用业务写入的模块才使用 `classifyWriteFailure`：明确失败、并发冲突、结果未知。POST 查询按读取处理，不能靠 HTTP Method 推断业务副作用。
- 网络超时、连接中断、HTTP 5xx、响应协议损坏或未分类异常后的事务结果均视为未知。共享 API 层提供稳定分类和安全错误信息，不自动重放写请求。
- 结果未知时阻断同一业务对象的后续危险操作，并保留原请求标识与编辑草稿。普通列表刷新、余额变化、当前字段或状态恰好符合预期，都不足以证明原操作已经提交，也不能解除阻断。
- 业务模块定义恢复过程；只有后端按原请求标识返回不可变提交事实、且原输入可核对时，才能把未知结果判为已提交。权威查询无结果或失败时继续阻断。缺少这种契约时记录待决项，不推断事务回滚。
- 版本冲突时读取最新对象或关系，保留用户草稿，并要求用户基于新版本明确确认；旧请求不得覆盖新目标或草稿。写入已成功而后续读取失败时只报告读取失败，不再次发起写入。
- 对不可替代的业务草稿和未知结果，应明确页面离开与重新进入后的恢复能力；需要跨页面恢复时由所属模块保存最小操作上下文，不放入通用写入状态机。

## 测试边界

- API 测试保护有意义的路径、方法、请求体、精度及错误分类契约；不为每个薄 API 函数机械创建独立文件。
- Composable/页面测试优先保护权限、状态迁移、乱序响应、并发版本、结果未知后的禁止重放和失败恢复。共享组件测试保护核心键盘、焦点和无障碍交互。普通 CRUD 拼装、简单绑定和字段赋值无需专测。
- 审查存量测试时，先列出每项保护的行为。保留关键契约与已修复的高风险回归；重复场景可参数化或合并，只有已被完整覆盖、失效或仅断言内部细节且无法发现有意义回归的测试才删除，并记录理由。Mock 不应取代实际行为断言。
- 新增测试须至少保护关键业务契约、复杂分支/边界、真实或高概率回归、共享组件核心交互，或补齐现有测试未覆盖的重要风险；优先扩展相关文件，不要求 Vue、Composable、API 一对一配套测试。
- `pnpm verify` 是完整质量门禁；模拟 API 的组件测试不等于真实 Gateway/后端联调。
