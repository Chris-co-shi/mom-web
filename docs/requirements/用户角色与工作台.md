# 用户角色与工作台

## 1. 目的

本文档定义 V1 中主要用户角色、核心任务和默认工作台关注点。角色名称用于需求和原型讨论，最终权限编码以 IAM 契约为准。

## 2. 内部角色

| 角色 | 核心任务 | 默认关注 |
|---|---|---|
| 集团管理员 | 组织、工厂、用户、Client 和治理配置 | 跨工厂概览、权限与配置异常 |
| 工厂管理员 | 工厂级配置、用户协调和运行监督 | 工厂运行状态、待办和异常 |
| 生产计划员 | 创建、下达和跟踪生产工单 | 待下达工单、物料可用、执行偏差 |
| 生产管理人员 | 监督生产执行和异常恢复 | 执行中工单、PCS 状态、投料偏差 |
| 生产操作员 | 查看任务和执行授权操作 | 当前工单、下一步动作、操作结果 |
| 仓库管理员 | 收货、库存、预占、入库和发运 | 待收货、库存异常、WCS 任务 |
| 质量检验员 | 执行检验和录入结果 | 待检任务、抽样、检验项和异常 |
| 质量经理 | 放行、不合格处置、偏差和 CAPA | 待放行批次、风险和超期事项 |
| 设备工程师 | 设备状态、故障和维护协同 | 设备异常、PCS/WCS 命令和恢复 |
| 集成管理员 | 外部接口、消息、重试和对账 | 失败调用、重复消息、积压和补偿 |
| 追溯与召回人员 | 批次影响分析和模拟召回 | 高风险批次、发运和客户影响 |

## 3. 外部角色

### 3.1 供应商用户

核心任务：

- 创建和维护送货单。
- 查看预约和到货状态。
- 查看来料检验结果。
- 补充不合格协同材料。

数据范围：仅所属供应商及授权工厂的数据。

### 3.2 客户用户

核心任务：

- 查看订单和交付状态。
- 查询发运和批次。
- 下载质量文件。
- 创建和跟踪客诉。
- 查看授权范围内的召回信息。

数据范围：仅所属客户组织及授权范围的数据。

## 4. 工作台设计原则

工作台不是所有统计图表的集合，应优先展示：

1. 用户当前必须处理的工作项。
2. 已经超时或存在风险的事项。
3. 需要用户作出决策的异常。
4. 关键流程的最新状态。
5. 可直接进入下一步操作的入口。

## 5. 工作项模型

每个工作项至少包含：

- 类型。
- 标题。
- 业务对象编号。
- 工厂。
- 当前状态。
- 优先级。
- 创建或更新时间。
- 责任角色。
- 可执行动作。
- 跳转目标。

## 6. 角色与权限关系

- 角色用于组织常见职责，不等于固定权限集合。
- 权限由 IAM 返回，前端根据权限控制可见性和交互。
- 数据范围由服务端强制执行，前端只传递筛选上下文和展示范围提示。
- 同一用户可以拥有多个角色，工作台应聚合而不是重复展示相同事项。
- 角色切换或工厂切换必须重新获取必要的权限和工作台数据。
