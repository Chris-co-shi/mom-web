# 权限与数据权限

## 1. 核心原则

前端权限用于改善用户体验，服务端权限用于强制安全边界。

```text
前端：隐藏、禁用、引导和提示
服务端：认证、授权、数据范围和审计
```

不得因为前端隐藏按钮就认为操作安全。

## 2. OAuth2.1/OIDC

浏览器应用采用 Authorization Code + PKCE。

每套应用独立维护：

- Client ID。
- Redirect URI。
- Post Logout Redirect URI。
- Scope。
- 发布域名。

不得把 Client Secret 放入浏览器。

## 3. Access 层职责

`@mom/access` 负责提供统一契约：

- 当前用户。
- 登录和退出状态。
- 权限码集合。
- 角色信息。
- 工厂和组织上下文。
- 路由元数据。
- `hasPermission` 等判断函数。
- 无权限与重新认证流程。

不负责：

- 服务端数据权限执行。
- 业务状态判断。
- 直接修改业务对象。

## 4. 权限层次

### 4.1 应用访问

决定用户是否可进入某一应用。

### 4.2 路由访问

决定是否可进入某个页面。

### 4.3 菜单可见

菜单根据权限和功能开关过滤。

### 4.4 操作权限

按钮、命令和对话框根据权限控制可见或可用。

### 4.5 数据范围

示例：

- 工厂。
- 组织。
- 供应商。
- 客户。
- 仓库。

数据范围由服务端强制，前端可展示当前范围和提供允许的筛选。

## 5. 路由元数据

建议包含：

```ts
interface MomRouteMeta {
  title: string;
  permissions?: string[];
  requireAllPermissions?: boolean;
  app?: 'mom-admin' | 'supplier-portal' | 'customer-portal';
  featureFlag?: string;
  factoryContextRequired?: boolean;
}
```

路由元数据不得硬编码服务端数据范围规则。

## 6. 角色使用规则

- 页面优先依赖权限码，不直接依赖角色名称。
- 角色可以用于工作台推荐和默认导航。
- 同一用户可能拥有多个角色。
- 权限变化后应重新加载菜单和相关上下文。
- 禁止在页面中到处判断 `role === 'ADMIN'`。

## 7. 403 与无数据的区别

页面必须区分：

- 没有访问页面的权限。
- 有页面权限但没有操作权限。
- 有权限但当前数据范围内没有数据。
- 数据存在但已被状态机禁止操作。

这些情况的提示和恢复动作不同。

## 8. 门户隔离

供应商门户：

- 服务端按供应商身份和授权工厂限制数据。
- 前端不提供任意供应商切换。

客户门户：

- 服务端按客户组织和授权范围限制数据。
- 前端不显示内部工艺、供应商和完整成本信息。

## 9. 工厂上下文

- 内部用户可能拥有多个工厂权限。
- 工厂切换必须触发必要数据失效和重新查询。
- 页面应明确显示当前工厂。
- URL、请求头或查询参数的具体传递方式以 Gateway 契约为准。
- 服务端仍需验证用户是否有权访问该工厂。

## 10. 验收

- 三应用独立 Client。
- 认证回调和退出路径明确。
- 权限判断集中在 Access 层。
- 菜单、路由和按钮无散落角色硬编码。
- 403、空数据和状态禁止可区分。
- 数据范围由服务端测试验证。
