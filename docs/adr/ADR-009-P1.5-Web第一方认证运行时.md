# ADR-009：P1.5 Web 第一方认证运行时

- 状态：Accepted
- 日期：2026-07-28
- 替代：[ADR-008：P1.5 Web 认证运行时](ADR-008-P1.5-Web认证运行时.md)
- 关联实现：[S08 Web 认证运行时实现](../architecture/S08-Web认证运行时实现.md)

## 1. 背景

P1.5 最终实现没有让三个 PC 应用直接执行 Authorization Code + PKCE，也没有把登录页面放在 IAM 服务中。IAM 是认证与权限微服务，MOM Admin、Supplier Portal、Customer Portal 各自承载第一方账号密码登录和首次改密界面。

仓库当前真实实现是 `@mom/first-party-auth`，旧 ADR-008 描述的 PKCE 运行时仍保留为标准协议兼容包 `@mom/auth`，但不是三个 PC 应用的当前登录入口。

## 2. 决策

1. 三应用继续固定 Client/user_type：
   - `mom-admin-web` / `INTERNAL`
   - `mom-supplier-web` / `SUPPLIER`
   - `mom-customer-web` / `CUSTOMER`
2. 三应用通过 Gateway 下的第一方接口登录、首次改密、刷新和退出。
3. IAM 不提供独立登录页面；登录 UI 属于各 Web 应用。
4. Access Token 与 Refresh Token 由 `@mom/first-party-auth` 保存到当前标签页 `sessionStorage`。
5. Token 不进入 `localStorage`、IndexedDB、普通 Cookie、URL、日志或持久化 Pinia。
6. 当前标签页刷新可以恢复会话；关闭标签页后会话数据消失；不做跨标签同步。
7. Refresh 使用 Single Flight；401 最多刷新并重试原请求一次。
8. `/api/iam/me` 继续提供用户、Client、user_type、Permission、Factory 和 Party 权限上下文。
9. 前端权限只改善体验，服务端执行最终授权。
10. `@mom/auth` 保留为 OAuth/OIDC/PKCE 兼容能力，不由当前三个 PC 应用直接调用。

## 3. 安全边界

- 无 BFF 的当前方案需要严格 CSP、依赖治理和 XSS 防护。
- `sessionStorage` 不是服务端授权证据。
- `X-Factory-Id` 只是工作上下文。
- Supplier/Customer 的 Party 绑定不可由前端自由选择。
- 登出请求失败时仍必须清理本地会话；服务端撤销由短期 Access Token、Refresh Rotation 和审计兜底。

## 4. 后果

### 正向

- 登录页面、品牌和交互由各应用掌控。
- 页面刷新无需重新输入账号密码。
- 不引入 BFF、CSRF Session 和额外部署单元。
- 三应用 Client、Token 和 Refresh Flight 相互隔离。

### 负向

- XSS 可能读取当前标签页 Token，必须维持严格前端安全门禁。
- 不提供跨标签登录状态同步。
- 未来切换 HttpOnly Cookie/BFF 必须重新做跨仓 ADR，不能局部混用。

## 5. 验收

- 三应用只调用 `@mom/first-party-auth`。
- 登录页只保留账号、密码；不提供图形验证码、短信验证码或手机号登录。
- Token 存储静态扫描通过。
- 401 Single Flight、首次改密、刷新恢复和退出清理测试通过。
- 三应用生产构建通过。
