# ADR-004：浏览器仅访问 MOM Gateway

- 状态：Accepted
- 日期：2026-07-18
- 关联架构：[API 访问与错误处理](../architecture/API访问与错误处理.md)

## 1. 背景

MOM 后端包含 IAM、MES、WMS、QMS、Integration 和 Traceability 等服务。若浏览器直接访问内部服务，会暴露内部拓扑、重复认证和错误处理，并使服务拆分变化直接影响前端。

## 2. 候选方案

### 方案 A：前端直接调用各微服务

优点：路径直观。

缺点：服务发现、跨域、认证、限流和版本治理分散，内部地址暴露。

### 方案 B：前端维护 BFF

优点：可针对页面聚合。

缺点：V1 增加新的后端运行单元和维护成本。

### 方案 C：浏览器统一访问 MOM Gateway

优点：认证、路由、限流、审计和上下文传播统一，内部服务可演进。

缺点：Gateway 成为关键入口，需要高可用和清晰契约。

## 3. 决策

选择方案 C。

三套浏览器应用只配置公开 Gateway 地址，不配置 IAM、MES、WMS、QMS 等内部服务地址。

## 4. API Client

`@mom/api-client` 统一负责：

- Gateway Base URL。
- OAuth Token。
- correlation ID。
- 统一响应与错误。
- 401/403/409/429/5xx。
- 超时、取消和幂等键。

## 5. 正向后果

- 后端服务拓扑不暴露给浏览器。
- 安全、限流和审计策略统一。
- 前端不依赖服务发现。
- 内部服务拆分变化对前端影响降低。

## 6. 负向后果

- Gateway 故障会影响全部应用。
- 需要处理 Gateway 聚合和错误语义。
- 前端无法绕过 Gateway 临时调用内部接口。

## 7. 验证

- 构建产物中不存在内部服务地址。
- `.env.example` 只提供 Gateway 和公开 OAuth 配置。
- 浏览器网络请求全部进入 Gateway。
- Gateway 错误携带统一关联标识。

## 8. 例外

第三方静态资源、公开文件 CDN 或经安全评审的专用下载域名不属于 MOM 业务 API，但必须单独记录来源和授权方式。
