# ADR-006：共享组件准入边界

- 状态：Accepted
- 日期：2026-07-18
- 关联架构：[设计系统与组件分层](../architecture/设计系统与组件分层.md)

## 1. 背景

Monorepo 很容易因为代码相似而不断向共享包提取组件，最终形成依赖复杂、变化困难的“万能组件库”。MOM 页面又包含大量特定状态和流程，过早共享会放大耦合。

## 2. 候选方案

### 方案 A：所有重复代码立即共享

优点：表面重复少。

缺点：不稳定需求被强行统一，组件参数膨胀。

### 方案 B：完全不共享领域组件

优点：应用独立。

缺点：状态表达、设计语言和稳定领域模式重复。

### 方案 C：基础能力统一，稳定领域模式满足准入条件后共享

优点：兼顾一致性和演进自由。

缺点：需要持续评审组件边界。

## 3. 决策

选择方案 C。

进入共享包至少满足：

- 被多个应用或多个领域页面稳定使用。
- 具有清晰 Props、Slots 和 Events。
- 不依赖应用 Store 或路由。
- 不直接访问 API。
- 输入为 View Model。
- 加载、空、错误和权限状态可表达。
- 有测试和文档。

## 4. 分层

- `@mom/design-tokens`：视觉 Token。
- 基础 UI：优先 Ant Design Vue。
- `@mom/common-ui`：Vben 已验证、且不依赖其完整 Monorepo运行时的页面级公共组合；不复制 `BasicLayout`、Menu、Tabbar、Breadcrumb、Preferences 和 Locales。
- 页面状态组件：通用 Loading/Empty/Failure 等。
- `@mom/domain-components`：稳定领域展示与交互。
- 应用私有组件：变化快或依赖页面编排的组件。

## 5. 正向后果

- 防止共享包过度膨胀。
- 应用可以独立演进。
- 稳定领域模式仍能统一体验。
- 共享组件更容易测试和维护。

## 6. 负向后果

- 短期存在合理重复。
- 需要定期识别可共享模式。
- 组件迁移可能需要调整调用方。

## 7. 验证

- 共享组件无应用依赖。
- 共享组件不调用 API。
- 共享组件具有消费者和测试。
- Vben 已有能力先复用或按来源登记迁移，不创建同职责的 MOM 替代品。
- 大量 `mode`/`variant` 参数需重新评估是否过度共享。
- 页面私有流程不会进入 `@mom/shared`。

## 8. 替代条件

若后续引入独立设计系统仓库或发布型组件库，应通过新 ADR 定义版本、发布和兼容策略。
