# 可观测性与前端诊断

## 1. 目标

让用户遇到页面失败、请求超时、异步任务异常或版本问题时，能够提供足够的诊断信息，并让运维人员将前端现象关联到 Gateway、后端服务、消息和设备链路。

## 2. 诊断维度

前端诊断至少包含：

- 应用名称。
- 应用版本或构建号。
- 当前路由。
- 发生时间。
- 浏览器和运行环境。
- correlation ID。
- trace ID（服务端返回时）。
- 业务对象编号。
- event ID、command ID 或 workflow ID（适用时）。
- 错误分类和错误码。

## 3. 请求关联

```text
页面操作
→ correlation ID
→ Gateway
→ 后端 Trace
→ 消息 / 命令 / 设备链路
```

前端不使用 trace ID 作为业务主键，也不自行拼接内部 Trace URL。

## 4. 错误采集

应覆盖：

- 未捕获 JavaScript 错误。
- Promise Rejection。
- Vue 组件错误。
- 路由加载失败。
- API 错误摘要。
- 静态资源加载失败。
- Source Map 解析所需版本信息。

不得采集：

- Access Token。
- Refresh Token。
- Client Secret。
- 完整表单敏感内容。
- 未脱敏文件内容。

## 5. 用户可见诊断

错误提示应提供：

- 用户能够理解的原因。
- 是否可以重试。
- 是否需要刷新或重新登录。
- 是否需要联系管理员。
- 可复制的参考编号。

示例：

```text
操作结果暂时无法确认，请不要重复提交。
参考编号：CORR-xxxx
可点击“查询最终结果”继续确认。
```

## 6. 关键用户流程事件

后续可记录低基数流程事件：

- 登录开始/成功/失败。
- 关键页面加载成功/失败。
- 命令提交开始/接受/失败/未知。
- 追溯查询成功/部分结果/失败。
- 文件下载成功/失败。

事件不替代业务审计，业务审计由服务端负责。

## 7. 性能观测

后续关注：

- 首屏加载。
- 路由切换。
- API 延迟。
- 大列表渲染。
- 谱系图加载与交互。
- 静态资源错误。

避免将用户 ID、批次号、订单号等作为高基数指标标签。

## 8. Source Map

- 生产构建可生成 Source Map，但必须有受控上传和访问策略。
- 不应默认公开 Source Map。
- Source Map 必须与应用版本绑定。
- 发布回滚后仍需能解析历史错误。

## 9. 诊断页面

`mom-admin` 后续可提供受权限控制的诊断抽屉或页面，展示：

- 当前应用版本。
- Gateway 地址的公开标识。
- 当前用户和工厂上下文摘要。
- 最近请求参考编号。
- 前端功能开关。
- 浏览器兼容性信息。

不得展示 Token 或内部服务拓扑。

## 10. 验收

- 错误提示包含参考编号。
- API Client 传播 correlation ID。
- 前端错误不会记录 Token。
- 应用版本进入构建和诊断信息。
- Source Map 有安全策略。
- 关键用户流程可与后端链路关联。
