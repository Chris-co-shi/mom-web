# 三应用职责边界

## 1. 目的

明确 `mom-admin`、`supplier-portal` 和 `customer-portal` 的用户、数据、路由、发布和 OAuth 边界。

## 2. `mom-admin`

### 用户

内部员工、管理人员和运维支持人员。

### 职责

- MOM 运营工作台。
- MES、WMS、QMS、Integration 和 Traceability 业务页面。
- 内部异常处理和人工接管。
- 权限和工厂上下文切换。
- 诊断和审计入口。

### 非职责

- 供应商自助提交入口。
- 客户自助订单和客诉入口。
- 后端配置或数据库管理界面。

## 3. `supplier-portal`

### 用户

供应商业务、物流和质量人员。

### 职责

- 送货单。
- 批次和包装信息。
- 预约和到货状态。
- 来料检验结果。
- 不合格协同。

### 边界

- 仅访问所属供应商授权数据。
- 不展示内部生产、库存成本或其他供应商信息。
- 独立 OAuth Client 和发布地址。

## 4. `customer-portal`

### 用户

客户采购、物流、质量和售后人员。

### 职责

- 订单与交付。
- 发运状态。
- COA 等质量文件。
- 客诉与处理进度。
- 授权范围内的影响分析和召回通知。

### 边界

- 仅访问所属客户组织数据。
- 不展示内部工艺、供应商或完整生产细节。
- 独立 OAuth Client 和发布地址。

## 5. 共享与隔离

| 能力 | 共享 | 隔离 |
|---|---|---|
| 技术栈和构建工具 | 是 | 构建产物独立 |
| API Client | 是 | Base URL/Client 配置可独立 |
| Access 契约 | 是 | OAuth Client 和权限集合独立 |
| Design Token | 是 | 品牌细节可覆盖 |
| 领域组件 | 稳定组件共享 | 页面组合和业务流程独立 |
| 路由 | 否 | 每个应用独立 |
| Store | 否 | 每个应用独立 |
| 发布节奏 | 否 | 每个应用独立 |

## 6. 外部数据最小化

门户页面必须遵循最小披露：

- 只显示完成用户任务所需字段。
- 不返回内部数据库主键作为业务展示标识。
- 不显示未授权组织、工厂、客户或供应商数据。
- 质量和追溯数据按外部可见契约裁剪。
- 错误提示不得泄露内部服务、SQL、堆栈或网络拓扑。

## 7. 跨应用跳转

V1 默认不支持依赖共享浏览器状态的跨应用深度跳转。

如需跳转：

- 使用明确 URL 和稳定业务编号。
- 目标应用重新校验登录、权限和数据范围。
- 不通过 LocalStorage 共享敏感业务状态。
- 不依赖两个应用同时发布相同版本。

## 8. 验收

- 三应用独立启动和构建。
- 三应用具有独立环境变量示例。
- OAuth Client 不混用。
- 门户数据范围由服务端验证。
- 共享包不存在应用私有页面和 Store。
