# MOM B2 UI 跨工具执行契约

- 版本：B2 / 2026-10-14
- 适用：mom-web 的登录、Shell、IAM、System、现有 MDM 及后续获准页面。
- 状态：设计与实施约束；不是“全站验收已通过”的证明。
- 读者：人工开发者及任意 AI 编码工具。无需获得历史聊天或安装特定技能。

## 1. 从这里开始

按任务风险读取（**无需每次读完整套文档**）：

1. **每个任务**先读 [根目录 AGENTS.md](../../../AGENTS.md) 与本契约相关章节；优先查实际组件代码和一个调用方。
2. **新建/调整 CRUD 交互**按需读 [CRUD 管理页标准](crud-management-page-standard.md) 对应章节；固定交互的字段/接口调整不用重读完整文档。
3. **全局视觉与 Token 变更**才深入读 [Design System](../design-system.md)；[ADR-003](../decisions/ADR-003-ui-foundation-migration.md) 是技术选型决策，常规页面不重复评审。
4. **产品信息架构/模块边界变化**才读 [产品体验](../product-experience.md)与[工程架构](../frontend-architecture.md)。
5. **回归既有视觉缺陷**时参考 [持续验收记录](../validation/web-foundation-v1.md)第5节；它是历史证据，不是日常输入的必读材料。

发生冲突先定位具体条款，不把历史计划或效果图自动当成当前实现。当前用户明确决策优先；涉及接口或领域边界时说明问题，不通过视觉改造偷偷改变业务规则。

## 2. B2 的可执行定义

- 浅灰画布、白色内容面板、青色主操作、柔和圆角、轻边框、微弱阴影；暗色主题保持信息层级。
- 控件/面板/弹窗圆角分别消费 `--mom-radius-control` / `--mom-radius-surface` / `--mom-radius-overlay`，当前映射12/20/24px。不要在页面复制色板和圆角体系。
- 名称先于编码；正文默认14px，辅助文字12–13px，管理页标题使用24px级别。不随宽屏同比放大字号和行高。
- 编码使用等宽字体，允许换行和完整查看；不把所有业务名称都做成等宽粗体，不以截断掩盖溢出。
- 图标使用现有 `@lucide/vue` 线性图标，常规16–18px。没有真实资源图标契约时用中性图标，不伪造资源类型。
- 主按钮纯色，不增加大面积渐变、装饰插画、通知系统、无依据的在线状态或新的品牌故事。

Token 的数值权威为 [primitives.css](../../../src/styles/primitives.css) → [semantic.css](../../../src/styles/semantic.css) → [components.css](../../../src/styles/components.css)。调整数值必须同步 Design System，不能只改效果图或业务页。

## 3. 组件与实现入口

| 需求 | 优先复用 | 页面负责什么 |
|---|---|---|
| 页面边界、标题、主操作 | `PageContainer`、`MomManagementHeader` | 标题Key、权限、刷新/创建用例 |
| 列表表面与工具栏 | `MomListSurface` | 查询范围、数据状态与插槽内容 |
| 数据表格 | `MomDataTable` | 列定义、格式化及最多两个常驻行操作 |
| 搜索/分页/更多操作 | `MomCrudSearch`、`MomCrudPagination`、`MomCrudRowMenu` | 服务端或当前页语义、分页参数、危险动作确认 |
| 模态框 | `MomModal`及footer插槽 | 字段、摘要、提交保护和结果未知流程 |
| 输入/选择/按钮/反馈 | `src/shared/ui/Mom*` | 受控值、校验、可访问名称和局部反馈 |
| 不可用/品牌 | `MomUnavailableState`、`MomBrand` | 准确的状态原因、恢复动作 |

入口目录：[shared/components](../../../src/shared/components)、[shared/ui](../../../src/shared/ui)。先读组件 Props/事件及一个真实调用方，再复用；不要凭本文猜测参数。优先 Reuse → Extend → Create，不引入万能 CRUD/Form，不绕过共享层直接复制 Reka 原语或原生基础控件。

权限分配是已有关系选择器，不强行套普通CRUD表格。其短分页8/16/24与普通分页10/20/50不同，保留局部分页组合，仍用Mom*控件；不因此扩大公共分页契约。

## 4. 状态必须能区分

| 状态 | 规则 |
|---|---|
| Default | 正常文字，弱边框或透明背景 |
| Hover | 未选中项轻微中性底色，不应看起来像另一个已选中项 |
| Selected | 默认浅青底；必须同时有aria-pressed/aria-selected或勾选语义，不单靠颜色 |
| Selected + Hover | 保持Selected的背景和文字组合，不能被通用按钮hover覆盖 |
| Focus-visible | 独立可见焦点环，不将键盘焦点当成已选中；不可被滚动边界裁掉 |
| Disabled / Loading | 真正禁用操作和重复提交，提供可见反馈；不能只降低透明度 |

国际化目录采用用户确认的实色选中变体：品牌底＋inverse文字，包含编码与状态；亮色是深青底白字，暗色消费对应主题Token。范围仅限该文案目录，不自动重做所有页面。

复查CSS层叠：基础控件 → 页面变体 → Selected/Hover组合。不能靠不断叠加 `!important` 修补状态冲突。

## 5. 自适应与滚动责任

- 不设全站1024px最小宽度；用弹性布局、`minmax(0, 1fr)`、换行和内容驱动断点，不使用整体缩放。
- Shell 随空间在完整侧栏、图标栏、导航抽屉之间切换；自动收敛与用户手动偏好分开。抽屉保留Esc、焦点约束和恢复。
- 主从页空间充足时并排，窄空间目录→详情单栏切换，返回保留查询、选择和分页。
- 表格仅在自己的容器内横向滚动，不撑宽页面；不能靠隐藏关键字段或整体overflow-hidden“修好”溢出。
- 查询工具栏、页码和按钮可换行；长名称不能把动作挤出视口。
- 权限分配弹窗只有MomModal正文滚动，左目录和右权限不独立限高滚动；标题/关闭及底部核对操作可达。其他确需独立滚动的复杂视图必须单独说明理由。
- Grid多行目录项必须按内容定高，不能在限高容器中挤压成普通按钮高度；禁止用隐藏文字解决重叠。
- Select/Dropdown采用现有Portal与层级Token，popover2200高于modal2100；不能在页面随意设超大z-index。

## 6. 页面及交互范式

**管理列表：** 标题/操作 → 对应区域反馈 → 查询/表格 → 分页。空数据、筛选无结果、读取失败分别呈现；失败不同时显示“无数据”。最多两个常驻行操作，其余进入更多菜单。

**主从目录：** 名称/说明主导，编码次级；当前选中明确。目录只代表实际加载范围，不把一页数据称作完整树。切换时旧请求不能覆盖新选择。

**权限分配：** 搜索/域筛选＋短分页目录 → 当前资源权限卡片 → 固定完整草稿计数/新增/移除 → 核对 → 一次整体保存。分页和搜索不清空草稿；200项、禁用权限、并发和结果未知约束仍有效。前端重读不是CAS。

**创建/编辑：** 宽度适度，字段标签及错误关联完整，首次错误可定位；保留重复提交保护。高风险变更继续确认；结果未知先重读核对，不自动重放写请求。

**国际化：** Web保存Key和Owner映射，真实译文归服务Runtime；不为目录每行请求译文。没有说明时诚实显示文案标识，不编造名称。管理列表按服务 Owner 加载全部文案；同一 Owner 的 Key 唯一，创建前统一转为小写，空白、全角及非 ASCII 字符就地提示用户修正。目录按ID识别，展示稳定 Key，搜索覆盖说明和 Key。编辑不得改稳定 Key；不同服务的数据不合并。相同 Locale 的完全相同译文只显示提醒和已有 Key，用户确认后仍可保存，不设置数据库唯一约束。当前接口沿用数组响应，目录是已加载集合的本地分页，不冒充服务端分页；文案规模增长后必须另行接入真正的服务端分页，不能无限扫描或静默截断。

## 7. 提交给用户前的验收清单

- [ ] 修改范围、复用组件、例外和接口边界已说明；没有覆盖用户已有改动。
- [ ] 正常/空/错误/加载/禁用状态明确；危险操作和结果未知路径保持。
- [ ] 点击选中后移出/再悬停，背景和文字不跳变；键盘焦点可见。
- [ ] 中文、英文长名称/编码可读；亮/暗/系统主题均检查。
- [ ] 连续改变可用宽度，采样390/768/1024/1280/1440/1920/2560及实际断点两侧；另查小高度、200%缩放。
- [ ] 主体无非预期横向溢出；弹窗正文和表格滚动边界明确，分页与保存栏不被遮挡。
- [ ] Esc、Tab、菜单、下拉及关闭后焦点恢复检查。
- [ ] 局部迭代先执行与改动有关的 lint/定向测试和必要类型检查；完成页面/Slice 或公共组件改动的交付前，按 `package.json` 执行 `pnpm verify`（lint/typecheck/test/build）并记录结果。不得以减少次数为由跳过最终门禁。
- [ ] 真实页面验收与静态命令分开。未打开浏览器、未联调、无真实数据的场景逐项标记未验证。

当前规则要求常规页面不新建测试文件；涉及行为时优先维护现有定向测试，必要新增须说明范围。不删除测试或放宽校验换取绿灯。

## 8. 更换工具时的任务开场模板

> 请先阅读AGENTS.md和本契约与当前任务相关的章节，以当前本地代码为准。复用现有共享组件，沿用B2和已确认的技术栈；不要自动读取所有历史报告、重新设计视觉或扩大模块范围。先定位任务关联代码、说明复用点与验证方式，再实现；按任务风险验证，交付列出实际完成和未验证项。

维护方式：视觉决策改Design System，交互规则改CRUD标准/本文，完成证据改验收报告；本入口只维护交叉引用，不复制整套Token或创建平行规范。效果图只能辅助Review，不能授权实现图中虚构的数据、按钮或能力。
