# ADR-013：Ant Design Vue 作为 MOM 基础组件库

- 状态：Accepted
- 日期：2026-08-02
- 接受日期：2026-08-03
- 决策人：Chris
- 关联架构：[UI 组件库](../frontend-architecture/03-ui-component-library.md)
- 替代：无

## 1. 背景

三应用已使用 Ant Design Vue 4.2.6。MOM 需要稳定的表单、表格、反馈和弹层基础，同时形成更克制的自有视觉语言并控制 Portal Bundle。

## 2. 问题

需要选择唯一基础组件库、主题适配方式和封装边界。本 ADR 不定义具体页面稿，也不批准升级组件库。

## 3. 候选方案

### A. 继续以 Ant Design Vue 为唯一基础库

迁移风险最低、企业控件成熟；需要集中主题化并约束深层覆盖。

### B. 更换组件库

可能获得不同默认视觉，但会扩大迁移、测试、Bundle 和无障碍风险。

### C. 全部自研 Headless 组件

控制力强，但 P1.6 成本和长期维护责任不合理。

## 4. 决策

选择 A，固定 Ant Design Vue 4.2.6 作为唯一基础组件库，使用 MOM 语义 Token 和集中 Theme Adapter 深度主题化。Lucide 是唯一图标集，通过静态 `iconKey` Registry 使用。Portal 按需引入组件。

## 5. 决策理由

该选择最大化现有代码和团队知识复用，把重构资源用于产品任务、运行时边界和一致性，而非重造基础控件。

## 6. 正向后果

- 三应用拥有统一交互基础和测试策略。
- Token 可同时驱动原语与 MOM 语义组件。
- Portal 可通过按需使用降低初始 Bundle。

## 7. 负向后果与风险

- 默认视觉需要系统性适配才能符合 MOM 方向。
- 过度包装会形成第二套组件 API。
- 深层 CSS 覆盖会被上游内部结构绑定。

## 8. 实施约束

- 页面可直接使用 Antdv 原语，稳定语义才进入 `common-ui`。
- 禁止第二 UI 库、第二图标集和未登记深层选择器。
- 共享组件不访问 API、Router、Store 或 Permission。
- 迁移期间不升级 Antdv。
- 新增或实质修改的 MOM 自有代码立即以 Antdv/Lucide 为唯一基础；现有 Vben 快照中的 Reka/Iconify 是冻结的临时例外，只允许被既有调用消费，不得新增依赖、调用或复制。
- 迁移例外必须在 S05 零引用、三应用构建、安全回归、关键 E2E 和 License/NOTICE 门禁通过后终止；未满足门禁时保留旧快照，不得把例外扩展成长期第二方案。

## 9. 验证方式

检查唯一依赖来源、主题/密度一致性、组件键盘与焦点测试、Portal 按需 Bundle、许可证台账和深层覆盖扫描。

## 10. 替代或回滚条件

只有真实场景证明 Antdv 无法满足性能、复杂交互或无障碍要求时，才以新 ADR 评估局部或整体替代；必须包含消费者、Bundle、许可证和退出条件。
