# 前端测试策略

## 1. 目标

测试体系应验证工程边界、类型契约、组件状态、关键用户流程和三应用独立构建，而不是只追求代码覆盖率数字。

## 2. 测试金字塔

```text
静态检查与边界校验
        ↓
单元测试
        ↓
组件测试
        ↓
API 契约测试
        ↓
关键流程 E2E
        ↓
视觉回归与人工验收
```

## 3. 静态检查

当前必须执行：

```bash
pnpm validate
pnpm check:type
pnpm build
```

后续应增加：

- ESLint。
- 格式校验。
- 循环依赖检测。
- 未使用依赖检测。
- 构建产物和 Bundle 分析。
- 文档与原型目录完整性校验。

## 4. 单元测试

适合测试：

- DTO 到 View Model 映射。
- 枚举和状态映射。
- 权限判断函数。
- 时间、单位和精度格式化。
- 幂等键生命周期。
- 错误模型转换。
- 追溯节点和边适配。

不应通过大量 Mock 测试简单 Vue 模板实现细节。

## 5. 组件测试

重点覆盖：

- Loading、Empty、Forbidden 和 Failed。
- Conflict、Rate Limit 和 Unknown Result。
- 表单校验和服务端字段错误。
- 权限导致的可见、禁用和隐藏。
- 命令提交中防重复点击。
- 异步任务状态和恢复动作。
- 领域组件 Props/Event 契约。

## 6. API 契约测试

应基于真实 OpenAPI 或稳定契约验证：

- 请求和响应 Schema。
- 枚举变化。
- 可空字段。
- 时间格式。
- 错误结构。
- 分页结构。
- 文件下载错误响应。

前端不得用长期手写 Mock 掩盖后端契约漂移。

## 7. E2E 测试

V1 至少覆盖：

### 通用

- 登录、刷新、退出。
- 401 重新认证。
- 403 无权限。
- 429 限流提示。
- 无效路由和错误边界。

### VS-01

- 供应商创建送货单。
- 管理端查看来料检验。
- 工单和 PCS 执行状态。
- 成品放行。
- WCS 入库异常恢复。
- 批次正反向追溯。
- 客户查看发运和提交客诉。

E2E 应使用隔离测试数据和可重复的后端/模拟器环境。

## 8. 视觉回归

适合覆盖：

- 三应用 Shell。
- 工作台。
- 列表和详情。
- 页面状态组件。
- 对话框和 Drawer。
- 谱系图关键视图。

视觉回归必须与原型差异评审结合，不能把所有像素变化都视为错误。

## 9. 可访问性测试

至少检查：

- 键盘访问。
- 焦点顺序。
- 表单标签。
- 对话框焦点管理。
- 颜色对比。
- 状态不只依赖颜色。
- 图形页面提供替代列表或文本信息。

## 10. 性能测试

重点场景：

- 大分页列表。
- 多条件筛选。
- 批次谱系大图。
- 工作台并发查询。
- 文件下载。
- 路由懒加载。

性能测试需记录数据规模和浏览器环境。

## 11. 测试数据

- 禁止使用真实客户或生产数据。
- 测试数据应有稳定业务编号前缀。
- E2E 应能创建和清理数据，或使用可重置环境。
- 并发和冲突测试需要明确版本和状态前置条件。

## 12. CI 门禁

合并业务页面前至少要求：

- 冻结锁文件安装。
- Repository Validate。
- Type Check。
- Build。
- 相关单元/组件测试。
- 关键流程 E2E（环境具备时）。
- 原型和文档链接校验。

## 13. 缺陷证据

缺陷记录应包含：

- 应用和版本。
- 页面与路由。
- 用户角色和工厂上下文。
- 操作步骤。
- 预期和实际结果。
- 截图或录像。
- correlation ID。
- 测试数据编号。
- 是否可稳定复现。

## 14. P1.5 MOM Admin 启动回归

2026-07-28 在 `/iam/users` 首次渲染时发现稳定运行时异常：

```text
ReferenceError: Cannot access 'sectionDefinitions' before initialization
```

根因是 `App.vue` 的 `setup()` 在模块局部 `const sectionDefinitions` 初始化前，
同步调用了会读取该常量的 `sectionFromRoute()`。类型检查和生产构建只验证静态契约，
不会执行组件 `setup()`，因此未能阻止该缺陷进入浏览器。

修复门禁：

- 路由 Section 定义与解析逻辑必须位于独立模块，不再依赖 `App.vue` 局部声明顺序。
- 单元测试必须覆盖六个合法 IAM Section 以及未知/缺失 Section 回退到 `users`。
- Repository Validate 必须确认 `App.vue` 使用已测试的 Section 导航模块。
- 最终验证继续执行类型检查、认证/权限测试与三应用生产构建。
- 浏览器环境可用时，必须补充 `/iam/users` 首次渲染和六个 IAM 菜单切换烟测。
