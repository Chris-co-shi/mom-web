# 前端总体架构

- 当前阶段：`P1.5：认证与授权闭环`
- Auth Runtime：[P1.5 Web 认证与授权运行时基线](P1.5-Web认证授权运行时基线.md)

## 1. 架构目标

`mom-web` 同时满足：

- 三套应用独立部署和独立第一方 Client。
- 统一工程、设计语言和浏览器 Auth Runtime。
- 共享认证、API、权限和领域组件边界。
- 不共享应用私有业务状态或 Token。
- 支持工业长流程、异步状态和故障恢复。
- 设计资产与实现共同版本化。
- 前端体验控制不替代服务端最终授权。

## 3. 应用层

每套应用负责：

- 独立布局、路由、品牌和构建产物。
- 独立 Client ID、运行时配置和当前标签页 Auth State。
- 应用私有状态和页面级数据编排。
- 结合 Permission 的路由、菜单和按钮体验。

应用之间不得共享 Token、Refresh Promise、Pinia Store 或应用私有业务状态。

## 4. 共享能力层

### `@mom/first-party-auth`

负责账号密码登录、首次改密、当前标签页 Token、Single Flight Refresh、退出和页面刷新恢复。

### `@mom/auth`

保留 OAuth/OIDC/PKCE 标准协议兼容能力，当前三个 PC 应用不直接使用。

### `@mom/access`

基于 `/api/iam/me` 负责用户、Permission、Factory 和 Party 的前端只读上下文，以及路由/菜单/按钮体验控制。

### `@mom/api-client`

负责 Gateway-only HTTP、Bearer Token、Correlation ID、`X-Factory-Id`、错误、幂等、超时和文件下载。

### 其他共享包

- `@mom/design-tokens`：设计 Token。
- `@mom/common-ui`：Vben 对齐的页面级公共组合；不承载应用壳、路由、Store 或 API。
- `@mom/domain-components`：稳定领域组件。
- `@mom/shared`：通用类型、格式化、校验和无业务工具。
- `@mom/traceability-graph`：批次谱系可视化边界。

## 5. 认证数据流

```text
应用启动
→ @mom/first-party-auth 恢复当前标签页会话
→ 无会话时显示应用内账号密码登录
→ POST /api/iam/auth/login
→ /api/iam/me
→ 校验 Client/user_type
→ 构建 Access Context
→ 恢复安全 returnUrl
```

页面刷新从当前标签页 `sessionStorage` 恢复；Token 不进入 localStorage、IndexedDB、持久化 Pinia、普通 Cookie 或 Vben Preferences。

## 6. 业务请求数据流

```text
用户操作
→ 页面校验
→ View Model / Command Mapping
→ @mom/api-client
→ Bearer Access Token + X-Factory-Id
→ MOM Gateway
→ 业务 Resource Server 最终授权
→ 统一响应或业务错误
→ 页面状态更新
```

`X-Factory-Id` 不是授权证明；Party ID 不由前端自由选择。

## 7. 配置边界

每套应用独立维护：

- Gateway 地址。
- Gateway 地址和固定第一方 Client ID。
- 应用名称、品牌、功能开关和构建版本。

不得配置：

- Client Secret。
- 内部微服务地址。
- 服务端 Permission/Scope 规则。
- 数据库或消息中间件凭证。
- 可自由切换的 Party ID。

## 8. 页面设计与安全关系

页面必须表达：

- 业务对象与当前状态。
- Permission 和当前 Factory。
- 可执行命令与后端并发条件。
- 异步结果、错误和恢复路径。
- 401、403、404、409、429、5xx。
- Correlation ID 和业务标识。

前端隐藏操作不表示后端允许或拒绝；最终结果以服务端为准。

## 9. 架构门禁

- 应用不能依赖其他应用。
- 共享包不能依赖应用。
- `@mom/first-party-auth` 不负责 Permission。
- `@mom/access` 不执行服务端授权。
- 领域组件不能直接调用 API。
- 页面不能直接使用持久化 Entity。
- API DTO 在边界层映射成 View Model。
- 浏览器只访问 MOM Gateway。
- Token 只进入当前标签页 `sessionStorage`，不进入长期存储。
- 动态菜单中心不是 P1.5 前置依赖。
