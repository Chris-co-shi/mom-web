# Web-P2-S06 角色赋权

## 编码前自查与边界

- 目标：在已实现的角色与权限目录之间完成 Role-Permission 的人工分配。赋权为“读取现状 → 跨页选择 → 核对新增/移除 → 整体替换”，不是多次增删。
- 数据所有权：Auth 持有 `auth_role_permission` 与事务；Web 不写数据库。浏览器只经 Gateway `/auth/**` 调用 `GET/PUT /auth/roles/{id}/permissions` 与分页 `POST /auth/permissions/search`。
- 权限：角色页需要 `auth:role:read`；入口与提交还要求 `auth:role:write`，选择目录要求 `auth:permission:read`。不要求 `auth:permission:write`，前端门禁不替代后端授权。
- 复用：既有角色页、统一 HTTP Client、`MomModal`、VXE 控件、Token 与主题体系；赋权独有的选择和并发语义留在 IAM 模块，不新建通用关系框架。
- 不做：用户—角色分配、批量角色赋权、权限即时生效、后端接口和生产依赖修改。
- 验证：角色关系 API/状态/UI 定向测试、`pnpm verify`、`git diff --check`；按用户此前要求不操作浏览器测试页面。

## DESIGN ISSUE

`PUT` 是无关系版本的整体替换。管理员 A 读取后，B 修改同一角色关系，A 再保存可能覆盖 B；前端在进入差异核对和最终提交前重读并比较基线集合，只能发现检查前已发生的变更，无法消除最后一次 GET 与 PUT 之间的竞态。当前方案可实现：**YES**。本轮不伪造 CAS，也不擅自扩展 Auth 契约；如果要求严格防覆盖，须由用户决定后端关系版本/条件写方案。

## 实现行为

调用链：角色行“分配权限” → `RolePermissionDialog` → `useRolePermissionAssignment` → `roles-api`/`permissions-api` → 统一 HTTP Client → Gateway → `RoleController`/`RoleApplication` → Auth 本地事务中的 Role-Permission 关系表。

- 初始读取目标角色、当前权限和资源元数据；选择业务域与资源或输入关键词后，权限目录按服务端条件与页码读取。已选集合跨页、跨筛选保留。最多选择 200 项；停用项不可新增，已有停用项可移除但不能保留后提交。
- 核对页明确列出新增和移除项，提醒保存会整体替换，已有 Token 不会刷新。空数组是“清空所有权限”的有意提交，仍须核对。
- 读到关系变化时阻止提交，明确要求读取最新关系并重新选择。未知写入结果不自动重放，关闭后再次打开仍先回到原角色核对。保存期间弹窗遮罩、禁关与重复点击保护。
- 角色行操作以已验收的用户管理为准：详情、编辑直接展示，分配权限和删除进入省略号菜单；不把赋权隐藏在编辑表单中。分配权限入口仅在同时具备角色写入和权限目录读取权时出现。

## 验收与风险

`pnpm verify` 已通过：Lint、TypeScript、22 个测试文件的 127 项测试与生产构建全绿；`git diff --check` 通过。测试覆盖关系 API 契约、跨页选择、200 项上限、停用项、目录失败、两次关系重读、未知写入阻断、权限变化及角色页弹窗与下拉交互。构建仍提示既有 VXE 共享资源大于 500 kB。前端自动化不等于真实 Gateway/Auth 联调。用户验收建议使用专用测试角色与测试权限，检查新增、移除、清空、跨页选择、已停用项、只读权限、并发重读与结果未知；不要修改 `PLATFORM_ADMIN` 或支撑其登录的权限集合。

- A（验收前）：真实读写与页面视觉、键盘、明暗主题由用户确认后才能标记 S06 完成。
- B（V1 边界）：关系无版本的最后写入覆盖风险、权限变化后须重新登录、服务端最多 200 项。
- C（当前过度设计）：通用授权树、审批流程和权限热更新均不属于本 Slice。

## 2026-10-05 交互修订

按用户确认，角色赋权不再首次加载全部权限的第一页，也不再做“仅当前页搜索”。打开弹窗仍读取角色及现有授权；资源元数据分页读取后提供“业务域 → 资源”两级选择。选定资源或输入关键词后才向 Auth 发起权限目录的服务端分页查询，关键词由后端匹配权限编码、名称、描述及资源名称。权限中文名称为主信息，技术编码仅作辅助识别；跨页已选集合不因筛选改变而丢失，保存仍是核对后的 `permissionId` 集合整体替换。资源元数据目前需逐页读取，若资源规模显著增大，应另行设计服务端业务域选项接口；本次不新增后端接口或生产依赖。
