# 前端总体架构

## 1. 架构目标

`mom-web` 需要同时满足：

- 三套应用独立部署。
- 统一工程和设计语言。
- 共享 API、权限和领域组件。
- 不共享应用私有业务状态。
- 支持工业长流程、异步状态和故障恢复。
- 设计资产与实现共同版本化。

## 3. 架构分层

### 3.1 应用层

负责：

- 应用布局和路由。
- 用户角色相关的页面组合。
- 应用私有状态。
- 页面级数据编排。
- 应用级品牌和 OAuth Client 配置。

### 3.2 共享能力层

负责：

- API 调用和错误模型。
- 登录和权限契约。
- 设计 Token。
- 稳定领域组件。
- 通用类型和无业务工具。
- 批次谱系图形能力。

### 3.3 后端访问层

浏览器只能通过 MOM Gateway 访问后端。内部服务发现、路由、服务间认证和领域事务对 Web 不可见。

## 4. 关键数据流

```text
用户操作
→ 页面校验
→ View Model / Command Mapping
→ @mom/api-client
→ MOM Gateway
→ 后端服务
→ 统一响应或业务错误
→ 页面状态更新
→ 用户反馈与诊断标识
```

异步流程：

```text
提交命令
→ 返回已接受 / 任务标识
→ 页面展示处理中
→ 轮询、事件或刷新查询状态
→ 成功 / 失败 / 超时 / 人工接管
```

## 5. 配置边界

每套应用独立维护：

- Gateway 地址。
- OAuth Client ID。
- 登录回调地址。
- 应用名称和品牌。
- 功能开关。
- 构建版本。

不得在前端配置：

- 内部微服务地址。
- Client Secret。
- 数据库连接。
- 消息中间件凭证。
- 服务端权限规则。

## 6. 页面设计与架构关系

页面不能只说明布局，还必须表达：

- 业务对象。
- 当前状态。
- 用户权限。
- 可执行命令。
- 后端并发或版本条件。
- 异步结果。
- 错误和恢复路径。
- 关联 ID 和业务标识。

## 7. 架构门禁

- 应用不能依赖其他应用。
- 共享包不能依赖应用。
- 领域组件不能直接调用 API。
- 页面不能直接使用持久化 Entity。
- API DTO 在边界层映射成 View Model。
- 权限判断统一经过 `@mom/access`。
- 浏览器请求统一经过 `@mom/api-client`。
- 工业状态必须使用后端权威枚举或映射契约。

## 8. 演进原则

- 先实现清晰边界，再提取共享能力。
- 共享包以稳定复用为条件，不因代码相似立即抽取。
- 复杂页面优先拆成状态模型和领域组件，而不是单个超大组件。
- 图表和大屏不能替代用户任务和异常处理。
- Vben 能力按切片引入，不复制完整演示工程。
