# Frontend Architecture 产品输入

> 状态：Approved with Deferred Items  
> 批准日期：2026-08-03 · Chris Review  
> 阶段：MOM Platform P1.6  
> 性质：后续 Frontend Architecture ADR 的产品约束，不是技术设计

## 1. 应用数量与边界

推荐保持三个 Web 产品应用：

1. `mom-admin`：内部制造协同与平台治理。
2. `supplier-portal`：供应商 Party 隔离的外部协同。
3. `customer-portal`：客户 Party 隔离的外部协同。

`mom-mobile` 保持独立现场渠道，不并入 Web 应用。本阶段不决定这些应用是否共享代码仓、构建工具或组件实现。

产品约束：三应用具有独立登录边界、用户类型、可见数据和业务动作；不能用运行时 Role Switch 合并。

## 2. 业务模块边界

前端产品模块应围绕用户任务与业务能力形成，而不是照抄后端部署单元。建议稳定边界为：

- My Work
- Inbound Collaboration
- Manufacturing Operations
- Quality Decisions
- Inventory & Fulfillment
- Traceability & Response
- Platform Governance

IAM 与 System 是 Platform Governance 的能力来源；MES/WMS/QMS 等后端边界可以影响契约所有权，但不能直接成为菜单或页面模块。跨模块共享业务事实时，各模块保留面向本任务的 View Model。

## 3. 导航与路由产品约束

- 产品信息架构决定一级域和任务名称。
- System Application Catalog 提供发布后的应用/导航元数据。
- 客户端只执行其已知且已注册的页面；未知 `routeKey` 必须 fail closed。
- IAM Permission 过滤导航与操作，但不能生成导航；后端负责最终授权。
- 无 Permission 引用的导航只表示登录可见，不表示页面内任何业务动作可执行。
- 跨域跳转以业务对象及关系为上下文，支持返回来源，不依赖菜单路径拼接。
- `System Application` 与 `OAuth Client` 必须在产品语言和管理界面中清晰区分。

## 4. 统一页面状态

每个数据页面必须对以下状态有可理解、可恢复的产品表达：

|状态|用户必须知道什么|最低可用行为|
|---|---|---|
|Loading|系统正在获取什么|避免重复提交；长等待可取消或离开|
|Empty|当前范围确实没有数据|解释原因，提供有权限且合理的下一步|
|No Result|筛选条件没有匹配结果|清除或调整筛选，不混同 Empty|
|Error|操作/加载未成功|说明影响、保留上下文、允许安全重试|
|Forbidden|已登录但无权访问|说明无权限，不泄露敏感对象|
|Not Found|资源不存在或按防枚举规则不可见|返回安全入口，不区分越权资源存在性|
|Conflict|数据已被他人或其他渠道改变|展示最新状态，禁止静默覆盖|
|Rate Limited|请求过于频繁|提示可重试时间，避免连续触发|
|Processing|后台业务仍在处理|显示可追踪状态，不伪装为完成|
|Partial|部分数据或动作不可用|明确缺失范围和是否可继续|

禁止以空白页、永久 Spinner、通用“操作失败”或静默回退掩盖状态差异。

## 5. 国际化、时区与单位

- 初始语言支持 `zh-CN`、`en-US`，跨服务使用 BCP 47 Tag。
- System 拥有动态 I18n 发布和用户显示偏好；客户端消费已发布内容，不把草稿当成线上文案。
- 技术时间点以 UTC/RFC 3339 语义交换，展示使用用户 `displayTimezone`；Factory 业务日期由 MDM 权威 IANA Zone ID 决定。
- System 拥有显示偏好，MDM 拥有 Factory 时区和单位换算；IAM 不拥有这些偏好，也不写入 Token。
- Locale、时区和显示单位均不是权限或业务事实。
- 精度敏感的数量、金额和计量值不得因展示层转换而丢失精度；换算后应标明单位和必要的原始值。
- 文案缺失时采用可诊断的受控回退，不能把内部 message key 直接展示给普通用户。

## 6. 权限体验

- 用户无权进入的导航和纯权限控制动作默认不显示。
- 用户通过深链接进入无权页面时显示受控 Forbidden；涉及对象枚举风险时按契约显示 Not Found。
- 因业务状态暂不可操作的按钮应禁用并解释原因；不能把“无权限”与“当前状态不允许”混为一谈。
- 高风险动作必须显示对象、影响范围和不可逆后果，并提供确认与操作结果。
- 前端可见性只改善体验，不作为安全证据；任何请求都接受后端拒绝并正确呈现。
- 多角色用户看到权限并集下的任务视图，不提供 Role Switch。

## 7. DTO 与 View Model 边界

- API DTO 表达服务契约，页面 View Model 表达具体用户任务；二者不得默认一一映射。
- View Model 只能组合页面所需字段，不把后端实体、权限对象或内部审计字段整包暴露给页面。
- 外部 Portal 使用独立的最小披露 View Model，不复用包含内部字段的 Admin 模型。
- 跨域页面可组合多个服务结果，但必须标记数据来源、更新时间、部分失败和冲突语义。
- 枚举、状态、日期、Decimal String、ID 等必须保持后端契约语义；19 位字符串 ID 不转成 JavaScript Number。
- 写操作模型只包含当前用例允许用户提交的字段，不能回传整个详情对象实现更新。
- UI 展示状态不得反向成为权威业务状态。

## 8. 响应式目标

|应用|产品目标|明确非目标|
|---|---|---|
|Admin|桌面优先，1024px 及以上提供完整体验；复杂表格、对比、流程与诊断可用|不承诺在手机完成全部管理与现场执行|
|Supplier Portal|360px 及以上的桌面和移动浏览器布局可完成核心查询、状态确认与轻量提交|不承载内部复杂配置或批量生产操作|
|Customer Portal|360px 及以上的桌面和移动浏览器布局可完成履约查询、证明查看和质量反馈|不公开内部运营页面|
|Mobile|手持设备、扫码、单手操作、弱网/离线任务优先|不承载完整 PC 计划、分析和治理|

- **Product Decision — Confirmed**：Admin 完整体验下限为 1024px；两个 Portal 的布局下限为 360px。
- **Unknown**：目标用户真实设备、浏览器矩阵、触控/平板要求和厂区网络分布。最小视口不替代真实设备验收。

## 9. 产品性能与可靠性目标

在缺少真实基线前，先定义用户可感知目标，不指定框架或实现：

- 页面必须尽早呈现结构与状态，不出现不可诊断空白屏。
- 用户提交动作必须即时获得“已接收/校验失败/处理中”的明确反馈，防止重复操作。
- 列表和复杂查询必须有范围、分页或其他容量控制，不一次加载无界数据。
- 切换 Factory、语言、时区后，用户必须能识别当前上下文，且不得显示上一上下文的残留敏感数据。
- 网络失败、超时和后台处理中均须可恢复；不得将“请求已接受”显示为“业务已完成”。
- Portal 在常见移动网络下仍应完成核心查询和轻量提交；Mobile 弱网/离线策略以任务风险分级。
- 性能验收应按角色关键旅程定义，而不是仅用构建体积或单一首页分数替代。

### 候选可测 SLO（尚未批准）

- 核心页面在标准企业网络下，P75 首次可操作时间候选目标不超过 3 秒。
- 用户动作在 100 毫秒内出现本地反馈；超过 300 毫秒的加载展示明确进行状态。
- 关键写操作不得因用户重复点击产生重复业务结果。

- **Need Product Decision**：批准或替换上述数字，并定义“标准企业网络”和关键旅程。
- **Need Backend Confirmation**：关键查询与写操作的服务端 SLO、异步处理和限流契约。

## 10. 可观测但不技术化的产品要求

- 用户可引用的业务操作应提供业务单号、任务号或事件关联标识，不向用户暴露 Trace ID 作为业务凭证。
- Diagnostic 页面围绕“哪个业务任务失败、影响什么、可采取什么动作”，不是基础设施监控大盘。
- 管理员需要区分权限拒绝、业务冲突、依赖不可用、异步处理中和最终失败。
- 外部 Portal 不显示内部堆栈、服务名、Topic、数据库或敏感诊断信息。

## 11. ADR 输入的禁止项

后续 Frontend Architecture ADR 不得推翻以下产品边界来换取技术便利：

- 不合并 Admin、Supplier、Customer 的身份与数据边界。
- 不以权限或微服务自动生成产品信息架构。
- 不让 Web 替代 Mobile、PCS 或 WCS 的现场/控制职责。
- 不复用内部 View Model 导致外部数据过度披露。
- 不把动态导航当成远程执行任意页面的机制。

本文不决定 Vue、React、Vben、UI 组件库、Design Token、CSS、状态库、请求库、目录结构和构建工具。这些只能在本组产品架构文档经 Chris Review 后进入 ADR。
