# MOM PC Web 产品体验与信息架构

## 1. 产品定位

MOM PC Web 是面向新能源材料制造场景的统一运营与管理工作台。它服务于平台管理员、工厂管理人员，以及后续的仓储、质量、生产、设备和能源等专业角色。

本应用的核心价值不是展示大量卡片，而是让用户在正确的工厂与业务上下文中，快速识别状态、定位异常、完成管理和作业决策。

### 1.1 当前边界

当前包含：

- MOM 内部 PC 管理端；
- 平台级 IAM、System、MDM；
- 后续按真实 Slice 接入的 WMS、QMS、MES 等模块。

当前不包含：

- 供应商门户、客户门户；
- PDA 或移动作业界面；
- 面向访客的官网；
- 独立大屏系统；
- AI 自动决策或没有真实后端契约的智能助手。

## 2. 设计原则

### 2.1 任务优先

页面先回答“用户要完成什么”，再决定展示什么。主操作保持明确，次要操作收敛，危险操作必须确认并解释影响。

### 2.2 状态优先

制造系统中的启用、停用、处理中、冻结、异常、不可用等状态必须同时使用文字、图标或形状表达，不能只依赖颜色。

### 2.3 上下文明确

用户必须随时知道当前模块、页面、筛选条件和数据范围。未来引入工厂上下文时，它只能作为业务或数据范围上下文，不能被前端误当成授权事实。

### 2.4 异常可行动

错误提示至少说明发生了什么、当前操作是否成功、用户下一步能做什么。稳定错误码、Correlation ID 等诊断信息应可复制，但不能把服务端堆栈或敏感信息直接展示给用户。

### 2.5 智能感来自解释能力

“智能”首先表现为关联信息、异常摘要、风险提示、趋势、推荐下一步和可追溯证据。没有算法或后端证据时，不显示虚假的 AI 预测、评分或建议。

## 3. 用户与主要任务

| 用户类型 | 当前或未来主要任务 | 体验重点 |
|---|---|---|
| 平台管理员 | 用户、角色、权限、字典、Locale、动态文案 | 权限影响清晰、变更可确认、并发冲突可恢复 |
| 主数据管理员 | 工厂结构、仓储结构、物料、计量单位 | 层级关系清晰、编码稳定、启停影响明确 |
| 仓储人员 | 入库、出库、库存、预占、容器 | 高效率扫描、库存状态和异常优先 |
| 质量人员 | 检验、放行、不合格处置 | 状态约束、证据完整、不可误放行 |
| 生产人员 | 工单、投料、过程、报工 | 时间顺序、设备/物料状态、失败恢复 |
| 管理人员 | 运营状态、异常、追溯与影响分析 | 聚合视图可下钻，指标定义可信 |

用户类型只描述体验目标，不代替 IAM 的角色和 Permission Code。

## 4. 全局信息架构

### 4.1 一级结构

```text
MOM PC Web
├── 工作台（在真实聚合数据和权限就绪后实施）
├── 平台管理
│   ├── IAM
│   ├── System
│   └── MDM
└── 业务运营
    ├── WMS
    ├── QMS
    ├── MES
    └── 其他经批准模块
```

业务运营模块的最终顺序由后续业务 Slice 决定。本结构只冻结分组，不替用户决定领域优先级。

### 4.2 当前模块导航

| 模块 | 页面组 | 当前依据 |
|---|---|---|
| IAM | 登录、用户、角色、权限、用户角色分配、角色权限分配 | Mini Auth 与现有 Controller |
| System | 平台字典、Supported Locale、`system.*` Message/Translation | ADR-043 与 System V1 Controller |
| MDM | 工厂结构、仓储结构、库位类型与库位、物料分类与物料、计量单位与换算 | MDM V1 Controller |

System 不包含 Parameter、User Preference、Application Catalog 或 Navigation。历史表或历史报告不能成为当前页面范围依据。

### 4.3 导航所有权

- Web 持有可执行路由、组件映射、静态菜单结构和静态翻译 Key；
- IAM 持有用户、角色、Permission Code 与最终认证快照；
- 各业务服务持有自身 API 与业务状态；
- 前端菜单过滤只能改善体验，不得替代后端 `@PreAuthorize`；
- 路由元数据使用稳定的 `routeName`、`titleKey` 和所需 Permission Code，不直接使用展示文案作为身份。

## 5. 全局应用框架

### 5.1 桌面布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 品牌/产品 │ 环境与系统状态 │ 全局搜索（未来） │ 主题/语言/用户 │ 56px
├───────────┬─────────────────────────────────────────────────┤
│ 一级/二级 │ 面包屑 + 页面标题 + 页面级操作                  │
│ 导航      ├─────────────────────────────────────────────────┤
│ 240px     │ 页面筛选、状态摘要、主体内容                    │
│ 可折叠64px│                                                 │
└───────────┴─────────────────────────────────────────────────┘
```

- 顶栏只承载跨页面能力，不放业务模块的局部操作；
- 左侧导航按模块分组，支持折叠，但必须保留可访问名称和 Tooltip；
- 页面标题区包含标题、简短说明、面包屑和最多一个主操作；
- 页面主体默认全宽，不为制造管理页设置营销网站式窄容器；
- 标签页导航不是 Web-P1 默认能力，只有真实多任务工作流证明需要时再引入。

### 5.2 页面范式

| 范式 | 适用场景 | 固定结构 |
|---|---|---|
| 列表管理页 | 用户、角色、物料等 | 标题/操作 → 筛选 → 批量上下文 → 表格 → 分页 |
| 树表管理页 | 工厂结构、权限树 | 左侧层级或树 → 右侧列表/详情；必须支持键盘与空状态 |
| 详情页 | 查看主数据和关系 | 摘要 → 状态/审计 → 分组字段 → 关联对象 |
| 创建/编辑页 | 中等复杂度表单 | 分区表单 → 影响说明 → 固定操作区；离开未保存提示 |
| 抽屉快速编辑 | 少量字段且无需复杂关系 | 保留列表上下文；不能承载超长流程 |
| 工作台 | 多源状态和异常聚合 | 指标定义 → 状态/趋势 → 异常队列 → 可下钻证据 |
| 关系/追溯视图 | 谱系、影响分析 | 可缩放关系图 + 列表替代视图 + 路径详情 |

## 6. 状态与反馈模型

所有数据页面至少覆盖：

1. 首次加载；
2. 局部刷新；
3. 正常数据；
4. 空数据；
5. 筛选无结果；
6. 无权限；
7. 请求失败；
8. 后端或网络不可用；
9. 保存中、成功、失败；
10. 乐观锁或版本冲突。

写操作反馈规则：

- 创建、编辑成功后说明对象与结果；
- 启用、停用、删除、重置密码、权限分配等高影响操作必须二次确认；
- 请求超时或响应未知时不得直接提示“操作失败且未生效”，应提示结果未知并引导刷新核对；
- 非幂等写请求不自动重放；
- 401 进入统一登录失效流程，403 展示无权限状态，两者不得混淆。

## 7. 响应式范围

PC Web 采用桌面优先：

- 主验收宽度：`1280–1920px`；
- 最低可用宽度：`1024px`；
- 平板横屏：允许导航折叠、表格横向滚动和操作收纳；
- 小于 `768px`：只保证关键提示和基础导航可读，不承诺完整后台操作体验；
- 移动作业由 `mom-mobile` 承担，不将复杂表格强行卡片化伪装成移动适配。

## 8. 可访问性

- 目标达到 WCAG 2.2 AA 的基础要求；
- 正文对比度不低于 4.5:1，大文本不低于 3:1；
- 键盘可完成导航、表单、菜单、弹窗和表格核心操作；
- 焦点样式必须可见，弹窗打开与关闭时正确管理焦点；
- 图标按钮必须有可访问名称；
- 表单标签、错误信息和输入控件建立程序化关联；
- 尊重 `prefers-reduced-motion`，关闭非必要位移与流光动画。

## 9. 明确禁止

- 大面积霓虹、发光描边、赛博朋克背景或无意义粒子动画；
- 为“科技感”滥用全屏深色、透明玻璃和低对比度文本；
- 首页堆叠没有行动价值的 KPI 卡片；
- 用颜色作为唯一状态表达；
- 没有真实数据和算法却展示 AI 预测、健康分或推荐；
- 一个模块自行创建独立的全局导航、主题、权限或错误体系。
