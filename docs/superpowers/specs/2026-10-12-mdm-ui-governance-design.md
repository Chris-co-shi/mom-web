# MDM UI 治理设计

## 目标

在不修改 MDM API、权限模型和数据模型的前提下，让现有 MDM 页面达到可理解、可操作、可访问的 PC 管理端基线。页面必须明确表达工厂、仓储、物料分类和计量单位的不同业务关系，而不是继续扩展同一套平铺 CRUD 外观。

## 设计边界

- 浏览器仍通过现有 MDM API 查询，服务端分页仍是权威。
- 不扫描全部分页构造伪全量树，不新增后端接口。
- 不新增生产依赖，不新建设计 Token，不重写共享组件库。
- 复用 `MomManagementHeader`、`MomListSurface`、`MomDataTable`、`MomCrudRowMenu`、`MomCrudPagination` 和 `MomModal`。
- Runtime i18n 继续由 `mdm.web` 数据库 Bundle 提供；前端不添加静态业务文案兜底。

## 页面结构

### 工厂与仓储结构

保留现有独立路由和服务端分页，在页面顶部增加清晰的层级上下文区。父级筛选展示为当前目录范围，列表只呈现该范围内的当前层数据；“查看下级”作为高频导航动作保留，启停进入更多菜单。

### 物料分类

在现有直接父级查询能力内采用“当前分类范围 + 子分类目录”，显示根分类或当前父分类上下文，不把已加载的部分分页伪装成完整分类树。详情展示分类名称、编码、父级、排序、默认保质期、状态和版本。

### 计量单位

量纲、单位类别、计量单位保留在同一路由，以完整可访问的 Tab 交互切换。每个 Tab 只展示自身目录；换算规则使用结构化版本记录，舍入方式使用可翻译文案。详情、编辑为常驻动作，启停和规则进入更多菜单。

### 普通物料

筛选区与列表形成同一管理任务，详情展示完整主要字段。引用选项仍按需分页加载，不把部分选项描述成完整数据集。

## 交互与无障碍

- 表格最多两个常驻动作，其余使用 `MomCrudRowMenu`。
- 弹窗标题必须区分创建、详情、编辑和状态变更。
- 字段错误与输入控件通过 `aria-invalid`、`aria-describedby` 关联；错误汇总使用 `role="alert"`。
- Tab 支持左右/Home/End 键、单一 Tab Stop、`aria-controls` 和 `tabpanel`。
- 亮暗主题只消费现有 MOM Token；1024px 下允许表格横向滚动，但筛选与标题区不得互相挤压。

## 验收

- MDM 页面不再出现超过两个常驻行操作。
- UOM Tab 的鼠标、键盘和焦点语义完整。
- 层级页面始终显示当前目录范围，不暗示全量树。
- 详情内容完整，错误能够定位到具体字段。
- `pnpm verify` 通过；无法执行的登录态浏览器检查明确记录。
