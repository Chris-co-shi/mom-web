# 文档维护约定

本文档定义 `mom-web` 的文档分支、中文命名、设计资产、README 风格和 PR 要求。

## 1. 固定文档分支

所有文档相关操作统一在：

```text
agent/complete-chinese-docs
```

适用范围：

- 根 README。
- 需求、计划和架构文档。
- ADR。
- 用户流程。
- 页面清单与状态矩阵。
- 原型图及原型说明。
- 组件映射。
- API、权限和数据范围映射。
- 测试、发布和开源来源文档。

禁止直接在 `main` 修改文档。

## 2. 标准流程

```text
同步 main
→ 在固定文档分支修改
→ 校验链接、Mermaid 和事实状态
→ 创建 Draft PR
→ 完成设计或架构审查
→ Squash merge
```

## 3. 命名约定

- 文档文件名优先中文。
- `requirements`、`plans`、`architecture`、`adr` 等一级目录保留英文。
- 垂直切片使用 `VS-NN` 前缀。
- 阶段计划使用 `Phase-NN` 前缀。
- ADR 使用 `ADR-NNN-中文标题.md`。
- 原型目录保留稳定英文切片标识，图片名表达页面与状态。

## 4. 设计资产要求

页面实现前必须具备：

1. 业务目标。
2. 用户角色。
3. 用户流程。
4. 页面清单。
5. 页面状态矩阵。
6. 原型图。
7. 组件映射。
8. API 与权限映射。
9. 错误、冲突、异步和恢复路径。

这些材料必须进入 Git，不以聊天记录、临时截图或个人本地文件替代。

## 5. README 风格

根 README 至少包含：

- 项目定位和状态徽章。
- 三应用和共享包。
- 技术基线。
- 前端全景图。
- 原型先行流程。
- 快速开始。
- 文档导航。
- 当前路线图。
- 架构与开源原则。

README 不得宣称尚未实现的业务、认证、路由或 API 已经完成。

## 6. 文档一致性

- `package.json` 和锁文件是版本权威来源。
- `docs/README.md` 是文档导航权威入口。
- 原型说明必须链接页面状态、组件映射和 API 映射。
- API 映射必须引用真实后端契约，不能自行发明字段。
- 权限文档必须区分前端体验控制和服务端强制授权。
- 决策变化通过新 ADR 替代旧 ADR，不静默重写历史。

## 7. PR 要求

文档 PR 必须说明：

- 修改内容和原因。
- 涉及的应用、共享包或垂直切片。
- 是否改变已有决策。
- 如何验证链接、Mermaid、原型和事实一致性。
- 是否只涉及 Markdown/图片等设计资产。

多个逐文件提交合并时使用 Squash merge。
