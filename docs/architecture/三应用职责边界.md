# 三应用职责边界

- 当前安全阶段：`P1.5：认证与授权闭环`
- Web 运行时权威：[P1.5 Web 认证与授权运行时基线](P1.5-Web认证授权运行时基线.md)
- 后端协议权威：[mom-platform P1.5 S00 PR #15](https://github.com/Chris-co-shi/mom-platform/pull/15)

## 1. 目的

明确 `mom-admin`、`supplier-portal` 和 `customer-portal` 的用户类型、Client、Party、Factory、路由、发布和安全边界。

## 2. 应用访问矩阵

| 应用 | Client ID | 允许 user_type | Party 规则 |
|---|---|---|---|
| `mom-admin` | `mom-admin-web` | `INTERNAL` | 不绑定外部 Party；代办通过独立权限和审计 |
| `supplier-portal` | `mom-supplier-web` | `SUPPLIER` | `party_id` 固定为账号绑定的 `supplier_id` |
| `customer-portal` | `mom-customer-web` | `CUSTOMER` | `party_id` 固定为账号绑定的 `customer_id` |

三套应用使用各自固定的第一方 Client ID，通过 Gateway 下的 IAM 第一方认证 API 登录；Token、Store 和 Refresh Flight 按应用实例隔离。

## 3. `mom-admin`

### 用户

仅 `INTERNAL` 用户。

### 职责

- MOM 内部运营工作台。
- MES、WMS、QMS、Integration 和 Traceability 业务页面。
- 内部异常处理和人工接管。
- IAM 用户、角色、Factory Scope、Mobile Access、Session 和安全审计管理页面。
- 当前 Factory 选择与业务上下文展示。
- 内部代办外部业务的受控入口。

### 安全边界

- 不提供供应商或客户身份切换。
- 内部代办不得冒充外部用户；必须由后端记录 Actor、代表主体和原因。
- 前端只展示代办上下文，不生成或篡改代表主体授权。
- 不作为供应商或客户自助入口。

## 4. `supplier-portal`

### 用户

仅 `SUPPLIER` 用户。

### 职责

- 送货单。
- 批次和包装信息。
- 预约和到货状态。
- 来料检验结果。
- 不合格协同。

### 安全边界

- `party_id` 来自后端 JWT/`/api/iam/me`，前端不得自由切换供应商。
- 仅访问所属供应商和授权 Factory 的数据。
- Factory 选择只能来自该供应商有效业务关系的授权子集。
- 不展示内部生产、库存成本或其他供应商信息。
- 对越权对象遵循服务端 404 防枚举语义。

## 5. `customer-portal`

### 用户

仅 `CUSTOMER` 用户。

### 职责

- 订单与交付。
- 发运状态。
- COA 等质量文件。
- 客诉与处理进度。
- 授权范围内的影响分析和召回通知。

### 安全边界

- `party_id` 来自后端 JWT/`/api/iam/me`，前端不得自由切换客户。
- 仅访问所属客户和授权 Factory 的数据。
- Factory 选择只能来自该客户有效业务关系的授权子集。
- 不展示内部工艺、供应商、成本或完整生产细节。
- 对越权对象遵循服务端 404 防枚举语义。

## 6. 共享与隔离

| 能力 | 共享 | 隔离 |
|---|---|---|
| 技术栈和构建工具 | 是 | 构建产物独立 |
| `@mom/first-party-auth` | 第一方协议与实现共享 | Client、当前标签页 Token 和刷新状态按应用实例隔离 |
| `@mom/auth` | OAuth/OIDC/PKCE 兼容实现共享 | 当前三个 PC 应用不直接使用 |
| `@mom/api-client` | 是 | Gateway/Client 配置可独立 |
| `@mom/access` | 契约共享 | `/api/iam/me` 权限集合和应用入口独立 |
| Design Token | 是 | 品牌细节可覆盖 |
| 领域组件 | 稳定组件共享 | 页面组合和业务流程独立 |
| 路由 | 否 | 每个应用独立 |
| Store | 否 | 每个应用独立，不共享 Token |
| 发布节奏 | 否 | 每个应用独立 |

## 7. 前端权限与服务端授权

- 前端路由、菜单和按钮只改善体验。
- Gateway 只做协议与粗粒度 Client 入口隔离。
- 业务服务负责最终 Permission、Factory Scope、Party Scope、对象归属和领域状态。
- `X-Factory-Id` 不是授权证明。
- 动态菜单中心不是 P1.5 前置依赖。

## 8. 外部数据最小化

门户页面必须：

- 只显示完成用户任务所需字段。
- 不返回内部数据库主键作为业务展示标识。
- 不显示未授权组织、工厂、客户或供应商数据。
- 按外部可见契约裁剪质量和追溯数据。
- 不在错误中泄露内部服务、SQL、堆栈、对象存在性或网络拓扑。

## 9. 跨应用跳转

V1 不依赖共享浏览器 Token 或跨标签 Token 同步。

跨应用跳转时：

- 使用明确 URL 和稳定业务编号。
- 目标应用使用自己的第一方会话，并重新执行 Client 和 user_type 校验。
- 不通过 localStorage、Cookie 或 BroadcastChannel 共享 Token。
- 不依赖两个应用同时发布相同版本。

## 10. 验收

- 三应用具有固定且不混用的 Client ID。
- Client 与 user_type 入口矩阵受后端和前端共同验证。
- Supplier/Customer Portal 无 Party 切换器。
- Factory 偏好不被描述为授权证明。
- 三应用不共享 Token 或 Refresh 状态。
- 门户数据范围和对象归属由服务端验证。
