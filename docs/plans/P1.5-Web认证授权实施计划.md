## 1. 仓库职责

`mom-web` 只负责浏览器运行时：三应用 Client 配置、PKCE、内存 Token、Single Flight Refresh、`/api/iam/me`、权限体验控制、当前 Factory 偏好和 HTTP 错误恢复。后端用户、Token、Session、RBAC、Factory/Party Scope 与最终授权语义仍由 `mom-platform` 定义。

## 2. 当前真实状态

S00 已完成设计对齐。S08 已进入实现：

- `@mom/auth` 提供 Authorization Code + PKCE S256、state、nonce、ID Token 校验、内存 Token、Refresh 与退出；
- `@mom/access` 已升级为 `/api/iam/me` 权限上下文和 Client/user_type 入口守卫；
- `@mom/api-client` 已实现 Gateway-only Bearer、Factory、Correlation ID、统一错误与 401 单次重试；
- 三应用已接入各自 Public Client 和顶层 PKCE 启动流程；
- Access/Refresh/ID Token 只存在内存，`sessionStorage` 只保存单次授权事务；
- 当前 Factory 偏好启动后必须根据 `/api/iam/me` 重新校验；
- Node 原生测试覆盖并发 Refresh、401 单飞、403 不刷新、重试上限和 PKCE 清理。

## 4. S08 验收

- 三应用固定矩阵：`mom-admin-web/INTERNAL`、`mom-supplier-web/SUPPLIER`、`mom-customer-web/CUSTOMER`。
- Public Client 不发送 `client_secret`，Redirect URI 精确配置。
- localStorage、IndexedDB、持久化 Pinia 和普通 Cookie 不保存 Token。
- Callback 校验 state、nonce、RS256 签名、issuer、audience 和 expiry，并清除一次性事务和地址栏协议参数。
- 并发 401 只产生一次 Refresh，每个业务请求最多自动重试一次；403 永不刷新。
- 页面刷新重新执行顶层 PKCE，不使用 hidden iframe 或跨标签页 Token 同步。
- `/api/iam/me` 的 Client/user_type 不匹配时安全拒绝进入应用。
- Supplier/Customer Party 固定，不提供主体切换器。
