# ADR-007：批次谱系图独立边界

- 状态：Accepted
- 日期：2026-07-18
- 关联架构：[设计系统与组件分层](../architecture/设计系统与组件分层.md)

## 1. 背景

批次谱系需要展示多对多节点和边、拆分、合并、返工、降级和影响分析。图形技术、布局和性能边界与普通表格组件明显不同，但权威谱系事实仍属于后端 Traceability 服务。

## 2. 候选方案

### 方案 A：每个页面自行实现图形

优点：局部自由。

缺点：交互、布局、性能和状态处理重复。

### 方案 B：把谱系业务规则和图形全部放前端

优点：页面看似独立。

缺点：前端会复制权威影响计算，产生一致性风险。

### 方案 C：建立独立图形包，只负责可视化和交互

优点：复用图形能力，同时保持业务权威在后端。

缺点：需要定义稳定节点、边和事件模型。

## 3. 决策

选择方案 C，使用：

```text
@mom/traceability-graph
```

该包负责：

- 节点和边的展示模型。
- 图形布局适配。
- 缩放、定位、选择和高亮。
- 筛选、层级和聚合交互。
- 节点/边点击事件。
- 加载、部分结果和失败状态的图形表达。

不负责：

- 计算权威谱系关系。
- 判断召回影响范围。
- 直接请求后端。
- 决定用户权限。
- 保存业务事实。

## 4. 输入模型

建议使用独立 View Model：

```ts
interface GenealogyGraphVM {
  nodes: GenealogyNodeVM[];
  edges: GenealogyEdgeVM[];
  partial: boolean;
  continuationToken?: string;
}
```

具体字段以 Traceability API 契约和页面需求为准。

## 5. 正向后果

- 图形能力可跨追溯页面复用。
- 后端保持权威事实和影响计算。
- 页面可以同时提供图形和列表视图。
- 性能边界可集中优化。

## 6. 负向后果

- 需要维护图形适配层。
- 大图性能和布局需要专项测试。
- 图形包与具体图库之间还需适配。

## 7. 性能与可访问性

- 不一次渲染无界节点。
- 支持层级限制、聚合或分页。
- 图形之外提供列表和详情。
- 不能只靠颜色区分关系类型。
- 键盘和辅助技术至少能访问替代信息。

## 8. 验证

- 图形包不依赖 API Client。
- 谱系事实来自 Traceability API。
- 拆分、合并、返工和降级可表达。
- 大图和部分结果有状态设计。
- 图形与列表选择保持一致。

## 9. 替代条件

若选定具体图形库或需要服务端图布局，应通过新的 ADR 记录技术选择、许可证、性能和迁移影响。
