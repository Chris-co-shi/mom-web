# 设计系统与组件分层

## 1. 目标

建立适合工业工作台的统一视觉语言和组件边界，避免三个应用各自定义状态颜色、表格密度和交互规则。

## 2. 组件层次

```text
Design Tokens
→ 基础 UI 组件
→ 页面状态组件
→ 领域展示组件
→ 领域交互组件
→ 页面与工作台
```

## 3. Design Token

`@mom/design-tokens` 至少管理：

- 品牌色与中性色。
- 成功、警告、错误、信息和禁用状态。
- 生产、质量、库存、设备与异步任务状态语义。
- 字体、字号和行高。
- 间距、圆角和阴影。
- 表格和表单密度。
- 布局宽度和断点。
- 图形节点和边样式。

状态 Token 必须同时提供颜色以外的文本、图标或形状语义。

## 4. 基础 UI 组件

优先使用 Ant Design Vue：

- 表格。
- 表单。
- 对话框。
- Drawer。
- Tabs。
- Alert。
- Result。
- Skeleton。
- Notification。

只有存在明确工业需求时才封装，不为统一而无意义包裹全部组件。

## 5. 页面状态组件

共享页面状态建议包括：

- `LoadingState`
- `EmptyState`
- `ForbiddenState`
- `FailureState`
- `ConflictState`
- `RateLimitState`
- `ProcessingState`
- `RecoveryState`

状态组件应允许页面传入业务上下文、恢复动作和排障参考 ID。

## 6. 领域展示组件

示例：

- 业务状态标签。
- 批次摘要。
- 库存数量分解。
- 工单状态时间线。
- 检验结果摘要。
- 设备或任务状态卡。
- 版本快照摘要。
- 关联 ID 诊断面板。

只接收 View Model，不直接调用 API。

## 7. 领域交互组件

示例：

- 放行确认。
- 驳回与原因录入。
- 人工接管确认。
- 重新执行或恢复。
- 批次筛选和追溯条件。

进入共享包前必须证明：

- 跨页面稳定复用。
- 权限和命令输入可通过 Props 表达。
- 不绑定单一页面 Store。
- 错误和处理中状态可配置。

## 8. 工业工作台布局

页面优先级：

1. 待办和异常。
2. 当前状态和风险。
3. 下一步动作。
4. 关键业务数据。
5. 趋势与统计。

不得用大面积装饰性图表挤占操作区域。

## 9. 表格规范

工业页面表格必须考虑：

- 稳定业务编号。
- 状态和更新时间。
- 工厂或组织。
- 默认排序。
- 可分享筛选。
- 服务端分页。
- 列宽与溢出。
- 批量操作边界。
- 空、加载和错误状态。

批量操作必须明确选择范围和影响对象。

## 10. 表单规范

- 字段按用户任务分组。
- 服务端校验映射到具体字段。
- 高影响操作显示后果。
- 草稿和已提交状态明确。
- 防止重复提交。
- 离开未保存页面时提示。
- 单位、精度、时区和业务日期明确。

## 11. 谱系图

`@mom/traceability-graph` 负责图形能力，页面仍需提供：

- 根批次和查询方向。
- 图形与列表切换。
- 节点和边详情。
- 过滤和层级控制。
- 大图聚合或分页。
- 加载、无结果、部分结果和失败状态。
- 键盘或替代可访问方式。

## 12. 验收

- 三应用使用统一 Token。
- 状态不只依赖颜色。
- 页面状态组件可复用。
- 领域组件不访问 API。
- 大表格和谱系图有性能边界。
- 原型中的组件均有明确映射。
