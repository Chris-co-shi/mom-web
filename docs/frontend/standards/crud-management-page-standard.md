# MOM PC Web CRUD 管理页交互标准

- 状态：项目级实施标准
- 适用范围：IAM、System、MDM 及后续 PC Web 中以列表、详情、创建、编辑、删除为主体的管理页
- 基线：IAM 用户管理的视觉语言；业务规则以各模块后端契约和 Slice 决策为准

## 1. 边界与优先级

本标准约束可复用的 UI 结构、交互和反馈，不决定字段、校验、权限码、状态机、事务或删除语义。冲突时按用户当前 Slice 决策、后端接口契约、已接受 ADR、本标准、历史页面代码依次判断；不能用 UI 一致性覆盖业务安全要求。偏离本标准须在对应 Slice 验证记录中写明原因、范围、替代交互和验收证据。

## 2. 页面骨架

1. 顶部为页面标题、简短说明；右侧依次放刷新与主要创建动作。创建入口按写权限显示。
2. 单一表格表面内依次为目录标题/提示、当前页筛选、范围说明、总数/当前可见数、密度切换、表格与分页。当前后端不支持全局筛选时必须明确写“仅当前页”，不得把过滤后的数量冒充服务端总数。
3. 数据表格使用共享 `MomDataTable`（TanStack Table v9），固定操作列至多保留两个常驻高频动作；其余动作通过统一行操作菜单承载。删除属于危险动作，不能直接在操作列常驻，必须进入菜单并在执行前二次确认。不存在的动作不显示，不用禁用按钮假装授权。
4. 服务端分页是权威。刷新保持当前页；切换每页数量回到第一页；创建成功回到第一页；编辑、删除与状态写入保留当前页，末页被删空时回退到有效页。搜索仅过滤当前已加载页，除非后端明确提供筛选契约。

## 3. 控件与视觉

- 页面上的按钮、输入、选择、弹窗、加载反馈优先使用 MOM 共享层及 shadcn-vue / Reka UI；业务页面不得重复实现基础下拉、弹窗、焦点或遮罩。`form`、`label`、`dl`、标题和普通布局容器保留语义 HTML。
- 页面级主/次按钮、表格工具、行内文本动作、状态标签、分页控件和弹窗底部操作统一使用 MOM Semantic/Component Token，支持亮色、暗色与跟随系统；不得复制页面私有色值或组件库全局覆盖。
- 行内图标按钮须有可访问名称、可见焦点；弹出菜单支持键盘触发、Esc 关闭、关闭后焦点恢复，并避免被表格裁切。菜单项用明确动作动词，危险项有独立语义色。
- 弹窗只使用 `shared/components/MomModal`；标题与关闭位由组件提供，正文只承载字段和必要上下文，底部右对齐取消/提交；不再复制第二套弹窗外壳。

## 4. 请求生命周期与反馈

- 首次读取、刷新、翻页、修改页大小和写入后重读必须在列表区域显示带文案的遮罩；成功或失败都解除。旧请求须取消或防乱序，旧页不得在失败时冒充新页。
- 弹窗保存期间显示局部遮罩、禁止关闭与重复提交。写请求默认不自动重放；保存成功与后续列表刷新失败是两个独立结果，不得因刷新失败重复写入。
- 正常成功应明确提示。服务端响应足以确认单行状态时，更新该行与版本；创建/删除及可能影响排序、过滤的编辑执行服务端重读。冲突、不存在或结果未知时，不乐观翻转，不盲目重试；提示刷新或重读目标以核对事实。
- 空目录、当前页筛选无结果、列表读取失败、无权限分别呈现，不用同一空表掩盖错误。错误提示保留可追踪 ID，但不得暴露 Token 或内部堆栈。

## 5. 状态动作的显式例外

状态列始终以文字加颜色表达；只读用户仅看到状态标签。只有状态独立、可逆、允许即时写入，且影响范围与后端契约已确认时，状态标签才可成为点击即保存的按钮。否则点击后进入统一确认弹窗。无论哪种模式，都要显示动作后果、保存中禁用、版本冲突与结果未知处理。

当前例外登记：IAM 用户启停经单独验收，为即时写入；IAM 角色与权限启停会影响后续登录授权，保留确认弹窗。不得为了让三页操作次数一致而静默修改此语义。

## 6. 组件边界与执行门禁

- 页面标题、说明和页面级操作使用 `MomManagementHeader`；目录标题、提示、工具栏、表格插槽、分页插槽及列表加载遮罩使用 `MomListSurface`。主从页可使用其 `embedded` 展示变体，资源选择、级联筛选等特有布局留在模块。按钮、工具区、计数、密度、表格和行操作采用 `mom-management-*` 语义样式，不再复制一套模块私有视觉规则；表格最小宽度等业务列差异仍由模块设置。
- 页面只编排模块 API、权限、业务字段和操作语义；当前页筛选统一用 `MomCrudSearch`，分页统一用 `MomCrudPagination`，行更多操作统一用 `MomCrudRowMenu`，弹窗统一用 `MomModal`（均位于 `src/shared/components/`）。加载视觉复用共享 `MomLoading` 与 MOM Token，不创建接受任意 API、字段 schema 和状态机的万能 CRUD 组件。
- 开始新页面前先查已有组件及样式。相同结构复用，稳定差异通过插槽/少量显式展示变体扩展；若不复用，须在 Slice 文档说明具体差异和替代方案。第三处相似实现出现时检查抽取价值，第四处不得未经评估继续复制。公共组件不能依赖业务 API、权限码或状态机，避免把“视觉复用”误做成“业务规则共用”。
- `shared` 组件不硬编码 IAM 权限码、文案或业务状态。模块仍负责按钮可见性、确认文案、字段校验和请求失败策略。
- 常规 CRUD 页面改动不新增 `*.test.ts` 文件。开发者应自查只读与写权限、两个常驻操作及更多菜单、删除确认、状态例外、当前页搜索、分页与遮罩、保存中防重复、冲突/结果未知、中英文；由用户进行页面人工验收。高风险业务规则若需自动化测试，须单独说明理由与范围。静态门禁禁止在管理页直接使用原生 `button`、`input`、`select` 作为交互控件。
- 提交前至少运行 `pnpm lint`、`pnpm typecheck`、`pnpm build`；人工检查亮/暗主题、1024/1280/1440/1920px、200% 缩放、键盘焦点与 Esc、中英文长文案。未做的项目报告为未验证，不能称为通过。
